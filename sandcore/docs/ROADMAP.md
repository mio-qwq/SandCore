## 2. 系统调用 ABI 草案（"SandCall"）

以下号段为历史草案；当前已落地的功能号、寄存器与返回值以 [SYSCALL.md](SYSCALL.md) 为准。

**原则：和 Linux 划清界限，从编号到调用方式都是自己的。**

- 触发方式：软中断 **`int 0x7C`**（0x7C = SandCore 的 S，且避开 Linux 的 0x80）
- 参数：`EAX` = 功能号，`EBX/ECX/EDX/ESI/EDI` = 参数 1-5，`DS` 必须指向用户数据段
- 返回：`EAX` = 0 成功 / 负数错误码；出错码体系自定义，不复用 errno

功能号分区（高位段做"命名空间"）：

```
0x0000-0x00FF  进程: 退出/派生/等待/让出
0x0100-0x01FF  内存: 申请/释放用户堆页
0x0200-0x02FF  文件: 打开/读/写/关 (走 SandFS)
0x0300-0x03FF  图形: 申请窗口/作图/事件轮询
0x0400-0x04FF  输入: 键盘/鼠标事件
0x7C00         探针: 读内核版本号 (第一个实现的功能, M5 用它自检)
```

## 3. SCX 可执行格式 → 已正式化

> **v0.5 起 SCX 规范正式落地**, 权威文档迁移至 docs/FS.md §3 (含 SCX1MIO 魔数);
> 系统调用见 docs/SYSCALL.md。下文保留为设计沿革。

**原则：内核加载器 30 分钟能读完的格式才是好格式。**

```
偏移  大小  字段
0     4    魔数 "SCX1"
4     4    入口 RVA (相对装载基址)
8     4    装载大小 (text+rodata+data 的字节数, 不含 bss)
12    4    bss 大小 (加载后清零)
16    4    栈大小 (建议值)
20    4    标志位 (bit0: 位置无关)
24    8    保留 (未来: 符号表偏移等)
32    ...  镜像主体 (装载到基址处)
```

- M5 起步版：**固定装载基址 0x400000**（用户空间底），程序由宿主侧工具链
  链接到该地址，格式里不含重定位表 —— 简单粗暴，先跑起来
- 进化版：支持基址表 + 少量重定位项，让多个程序共存

### 宿主侧工具链（配套）

| 工具 | 职责 |
|---|---|
| `sc-ld`（先做成 mkimg 的兄弟脚本） | 把用户程序 .o 链到 0x400000 并封成 SCX |
| `sc-mkfs` | 往磁盘镜像 LBA 65+ 写入 SandFS，安装 SCX 程序 |

**格式一致性红线**：内核加载器解析 SCX 的代码、sc-ld 生成 SCX 的代码、
本文第 3 节的表格，三者必须同步修改，提交信息里注明"SCX 版本未变/已升级"。

## 4. SandFS 存储草案（历史沿革）

当前SandFS v4在**独立IDE数据盘LBA0**：新盘80扇区/512项/数据81，
历史32扇区/192项/数据33按原位读写兼容；
引导软盘 LBA 65+ 仍是保留区。以下旧草案不应用于打包器，正式布局见 [FS.md](FS.md)。

引导区之后（LBA 65+）的自研文件系统，原则：**能为 30 个程序和资源文件
服务的最小设计就是好设计**。

```
LBA 65:   超级块 (魔数 "SANDFS", 版本, 块大小, 文件数)
之后:     文件目录表 (定长条目: 名字[32], 起始 LBA, 扇区数, 大小, 标志)
之后:     文件数据区
```

不做：目录树（一层平铺够用）、权限位（单用户玩具）、日志（掉电重来）。
未来的进化点在 ROADMAP 的 M7+ 再议。

## 5. 用户态与多任务草案（历史沿革）

当前实现是低地址内核恒等映射 + 每任务私有 `0x400000..0x7fffff` 映像/栈区，
M8新增私有`0x40000000..0x43ffffff`图形堆；
没有采用高半内核；PIT 100Hz 抢占、聚焦 owner 输入、退出后安全释放资源已实测。
EXEC 异步启动，不含 wait/IPC；正式布局和生命周期见 [MEM.md](MEM.md)、[SYSCALL.md](SYSCALL.md)。

- ring 3：用户代码段 DPL=3，系统调用经 `int 0x7C` 陷入（IDT 对应门设 DPL=3）
- 每进程独立页目录；内核线性映射高 1GB（0xC0000000 起）—— 这一步会
  把内核改成高半内核（higher-half），是 M5 最大的结构手术
- 调度：先抢占式轮转（PIT 100Hz），M6 观察是否加简单优先级老化
- 进程间通信：M5 只给"父子等待"，消息队列按需加

## 6. 自举（self-hosting）路线

"几乎可自举"的判定标准与阶梯：

1. **格式自描述** ✅：SCX/SandFS/SCF 已正式落 [FS.md](FS.md)，SandCall 见 [SYSCALL.md](SYSCALL.md)，不再等待另建 SCX.md。
2. **宿主工具链对齐** ✅：mkscx/mkfs/mkscf 与内核读同一版布局，SCX 头 36B、固定基址 0x400000；资源经 build/fs 统一上盘。
3. **源码级自省** ✅ 基础功能通过：Files/Studio 打开编辑源码，Debug 读取真实目标内存/指令与符号图；独立 SCX 容器十六进制编辑器尚未实现。
4. **原生汇编器** ✅ 自动化通过：ring3 SandAsm 两遍 NASM 子集编译，`asm home/demo.asm apps/demo.scx` 在系统内输出 SCX，随后实际运行。
   截图 `build/m6/04-native-assembler.png`、`05-generated-program.png`；语法与上限见 [ASM.md](ASM.md)。

   完全大写 SCAPI.H 内联系统调用。证据 build/m7-compiler/，完整语言/容量见 C.md；内核整机重建尚未自举。
