## 1. 设备与卷的区别

双盘启动：sandcore.img是2880个512B扇区的引导软盘，保护模式ATA
驱动不能访问FDC。sanddata.img挂IDE主盘；真实容量来自IDENTIFY，
卷范围来自校验过的SandFS超级块。当前SandFS直接从设备LBA0开始，
没有MBR/GPT分区表；partitions如实列整盘卷，不捏造第一分区。

## 2. STORAGEINFO固定32个u32

0x7A：EBX=完整128B缓冲，成功0，非法映射-1且整块不写。

| 字偏移 | 含义 |
|---|---|
| 0/1/2/3 | 版本1、ATA设备在场(0/1)、扇区512B、实际ATA扇区数 |
| 4/5 | 引导软盘合同2880扇区(非FDC枚举)、ATA接口1=LBA28 |
| 6/7/8 | SandFS有效标记、卷格式版本、有效卷声明扇区数 |
| 9/10/11 | 数据首LBA、追加高水位LBA、还能追加的空闲扇区 |
| 12/13/14 | 目录容量、已用条目数(含显式空目录)、目录扇区数 |
| 15/16/17 | 活跃文件占用扇区、活跃字节、历史洞扇区 |
| 18 | 布局标记1=整盘SandFS卷；无效卷为0 |
| 19..31 | 保留0 |

卷无效时6..18为0，真实设备容量仍可查询。空闲来自追加高水位，
不是`总容量-活跃字节`；现有FS删除不回收历史数据洞，因此df同时
说明该区别。API不提供任意扇区写入，核心路径保护继续在内核拦截。

## 3. 容量扩展与兼容

新发布v4目录80扇区，512项72B条目，数据从LBA81开始。原v4/32扇区
192项及旧40B条目盘保持原位读写，不在开机时移动旧数据。宿主构建
验证完整旧盘并备份后重排成80扇区，用户文件/配置按已有合并规则
保留；不静默截断超量条目。详见FS.md。

## 4. 修订记录

ATA多扇区写入在每个512B的PIO数据阶段后检查设备完成/ERR/DF；
本次调用全部扇区完成后执行一次FLUSH CACHE，最终flush成功才返回0。
部分数据或flush失败仍返回-1，不能声称部分写入回滚。SandFS仍先
提交新正文/备用目录bank，最后超级块切换；该顺序和不确定提交时
fs_faulted停止写入的合同不改。此批次化使384扇区目录bank每次从
384个flush降为1个，不减少持久化提交点、不改变文件或像素质量。
