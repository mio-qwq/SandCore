# SCMEM：三环批量内存源库 v1

作者mio，2026-10-04。这是公开可复用的源级库，`SCMEM.H`声明，
`SCMEM.inc`实现；上盘为SYS/SRC及SYS/INC，SCAPI内核ABI不变。
当前实现已在scmem-01/02由真实M7/G2编译，1880内存用例/72裁剪矩形
全字节与返回值/严格页回收通过；性能夹具仍另测。缓存资源与栅格绘制需要廉价搬运和清空，
不能预生成完又在每帧以低效逐元素表达式循环复制数MB。

| 源入口 | 长度单位 | 行为 |
|---|---|---|
| sc_mem_copy(dst,src,bytes) | 字节 | 非重叠复制，返回原dst；相同地址直接返回 |
| sc_mem_move(dst,src,bytes) | 字节 | 重叠安全；后向重叠逆序复制，其余前向 |
| sc_mem_fill(dst,value,bytes) | 字节 | 写value低8位，返回原dst |
| sc_mem_fill32(dst,value,words) | u32项 | 精确写words项，返回原dst |

调用者拥有全部内存和缓存生命周期。正长度须全部可读/写且区间
不越u32地址末端；库不申请内存、不悄悄裁短，也不隐含FRAME提交。
零长度不解引用，可传空指针；copy的不同非空区间不能重叠。
i386 REP允许非对齐地址，copy主体为四字节项，再精确复制0..3字节
尾部；护栏和下一对象不得被宽写覆盖。fill32长度不能误当字节。

新SCCC预定义`__SCCC_REP__=1`，其内联汇编追加四种字符串指令：
`rep movsb/movsl/stosb/stosl`。采用已有+S/+D/+c与a固定寄存器约束；
每个REP入口先CLD，不设置STD，cdecl保留寄存器仍由后端保存。
没有浮点/SIMD、libc或新增线程上下文。后向重叠用整数C逆序，避免
DF=1被抢占中断带入内核。新宏只表示真实存在的这四种汇编能力。

已验收M7和较早SCCC没有能力宏，预处理选择相同语义的整数C分支；
旧编译器不必先认识REP模板，就能编译新版SCCC的NUI界面。G1生成
G2时新能力宏启用，之后G2/G3应收敛。GCC走同一REP分支，仅作为
引导构建或诊断，不冒充系统内编译产物。

NUI在原裁剪完成后使用fill32，全宽连续行合并为一次批处理；窄
矩形仍每行填span项。先判空再转u32，保持裁剪、透明高字节、色值
和stride空隙不变。新库不缓存最终图像；游戏资源失效仍归上层。

验证须覆盖零长、非对齐、四字节尾部、同地址/前后重叠、各长度
护栏和返回指针、原M7 C回退及新G2 REP、完整NUI裁剪参考与严格页
回收。另测相同尺寸/真实不同内容的缓存帧搬运+提交+合成基线，以
估计预生成方案的固定成本；它不是完整游戏或实时光追的性能上限。
