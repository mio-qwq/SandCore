# 私有工程备份（2026-10-05）

仓库：https://github.com/mio-qwq/SandCore ，保持私有。
按用户最新要求，Git保存完整工程代码、资源、文档、测试工具及许可证，
另保存每版本一次构建产物。全部本机原始数据继续保留。

## 文件范围

- 根目录及`sandcore/`：当前M9工程、M8冻结实现、规范/验收截图和全部第三方源码/声明。
- `snapshots/M6/`、`M6a/`、`M7/`、`M8a/`：原交付包中的完整非build工程文件，保留原字节。
- `releases/`：M6/M7/M8a/M9各一个精简ZIP；每包只有一套启动盘与数据盘，配套启动工具和摘要。
- `history/`：旧build/试玩目录及原ZIP中的额外源码、脚本、文档、许可证和影片工程输入；
  不同内容只保存一次，INDEX.json记录原位置和SHA256，相同内容引用当前工程/快照。
- 根目录字体ZIP、字体资产及原始M9/M10路线文档：保留所需资源生成输入和项目讨论参考。

精简构建包仅重新压缩既有文件，不重编译旧版本、不修改盘内内容。
包内`manifest.json`列每个文件SHA256及原交付成员路径；仓库的
`releases/MANIFEST.json`记录固定原包摘要、历史源码逐文件摘要及精简包摘要。
打包后实际重新打开ZIP校验全部CRC、尺寸和SHA256，前后核对原交付ZIP摘要。

M9仅保留默认来源盘；原双盘专项证据和备用盘在本机验收包中保留。

## 从仓库构建

根目录`build.bat`现在默认构建M9，输出`sandcore/build/m9-work/`。
`build-version.bat M6a|M6|M7|M8a`在独立`rebuild-output/<版本>/`重建对应源码快照，
历史原文件不改动，已有输出拒绝覆盖。WSL需GCC/ELF binutils/NASM/Make/Python，
资源生成另需Pillow（WSL安装或PATH中带Pillow的Windows python.exe）。

M9及M8a的历史字节读取器现在可从本仓库的精简M7/M8a构建包和源码快照读取，
逐项核对固定摘要；不再要求本机原M7/M8a大ZIP。原ZIP存在时仍按原摘要核对。
保留已发布LEGACY原字节需要仓库内的基线镜像，这是明确的兼容输入；
精简ZIP与原ZIP各有独立摘要，没有冒用文件名或原ZIP摘要。

五份源码在独立干净克隆中实际构建通过，M9启动盘与既有验收盘字节相同，
并通过Windows QEMU串口传输17项、系统内SCCC编译/执行和HMP桌面截图。
详细记录、源码完整性核对及宿主/原生发布边界见[REBUILD-VERIFICATION.md](REBUILD-VERIFICATION.md)。
这次历史构建是用户要求的可重建性核验，不重启M8功能开发、性能优化或影片渲染。
