## 1. SandFS v4（可写，新盘512项完整路径）

| 区域 | LBA | 内容 |
|---|---|---|
| 超级块 | 0 | `SANDFSMIO`(9B) + 保留(3B) + 条目数(u32 @12) + 目录扇区数(u32 @16，新80/旧32) + 版本(u32 @20=4) + 扇区数(u32 @24，0=旧16384) |
| 目录表 | 新1..80/旧1..32 | 新512/旧192项，每项72B: 文件名(63B UTF-8 + NUL) + start_lba(u32 @64) + size(u32 @68) |
| 数据 | 新81+/旧33+ | 文件内容顺序排列、512B对齐；M8默认64MB=131072扇区，旧8MB/零容量字段继续支持 |

- 新盘最多512项；历史v4/32扇区仍192项。旧v1/v2一扇区与v3八扇区
  仍按原40B项读写，名字限31B；开机不移动旧盘数据。
- 目录/元数据在验证超级块后按实际容量申请物理页；新盘9页条目+10页
  元数据，失败全部释放/卷无效；常驻页属于内核，不计某个应用泄漏。
  rename临时页所有分支释放，list回看去重无额外静态大表。Files、
  CLI和NUI文件选择器同步支持512项，不截成192条。
- **伪目录** (v0.2): 文件名允许带路径前缀, 约定命名区:
  `sys/` 字体/图标/配置 ｜ `bin/` 可执行命令(shell/asm) ｜ `apps/` 应用 ｜ `desk/` 快捷方式(.lnk) ｜ `home/` 用户文本与源码
  —— M7 从完整路径动态推导直接子目录。start_lba=0 且 size=0 是显式空目录；无目录 inode/父子链表。
- **可写** (v0.2): `fs_write()` 已存在已重写则原地覆盖, 放不下/新文件追加到数据末端,
  超级块计数与目录表自动写回 (`write_meta()`); ATA 写 = `ata_write_sectors()`
  (PIO 逐扇 + 0xE7 FLUSH CACHE);
- 内核侧: `fs_init()` 用 ATA PIO 驱动读超级块与目录表;
- 上盘工具: `tools/mkfs.py` v2 —— 递归 `build/fs/` 目录树, 相对路径即文件名。
  Makefile 生成 `build/fs/sys/font.scf`，mkfs 只遍历目录树；超过目录容量直接失败，不静默截断。
  读写末扇区均经 512B 中转缓冲，只复制实际长度，避免用户缓冲区越界。
  v4 路径超过 63B 时拒绝创建，不截断名称。根斜杠/重复斜杠/`.`/`..` 先规范化，越过根/反斜杠/冒号/空格拒绝；查找忽略 ASCII 大小写，显示保留拼写。
  ATA 必须 BSY 清零且 DRQ 就绪才传数据，ERR/DF/超时返回失败；元数据写失败也返回 -1。

### M7 文件操作与核心保护

FSDIR 只返回直接子项，逐行 `D/F 名字 大小\n`，多个共同前缀去重；整列表 NUL。
MKDIR 创建显式空目录，REMOVE 只删文件/空目录，RENAME 修改整组目录前缀，
先检查新名字长度、冲突与不能移动进自身后代。STAT 返回类型（1 文件/2 目录）及大小。
系统调用先规范化后拒绝三环写入/删除/重命名 `SYS/CORE` 及后代，移动其祖先也拒绝，
返回 -5。这是内核入口保护，不是磁盘权限位；可信零环 fs_write 可写，用户自定义
模块位于 `SYS/MOD`，核心模块 `SYS/CORE/CORE.SKM` 的格式和自动加载见 MODULE.md。

### 持久化与构建盘的区别

应用直接写 QEMU 挂载的数据盘；关闭再重启 QEMU，文本与壁纸配置仍在。
M7历史打包器在资源依赖改变时重建目录表；M8已改为合法v4盘合并，保留用户条目，详见本页后文。构建前仍备份sanddata.img。
自动验收始终用数据盘副本，避免用测试文件覆盖交付盘。没有垃圾回收或掉电日志；文件变大追加，旧扇区暂不回收。

## 2. SCF1MIO 字体文件

```
偏移  大小  内容
0     7    魔数 "SCF1MIO"
7     1    NUL 保留字节
8     4    字形数 (u32 LE)
12    ...  每字一条: UTF-8 汉字(3B)+NUL(1B) + 16 行 × (16 列 + NUL)
```

- 来源: `kernel/font16.txt`（用户 mio 所有，凤凰点阵体 CC0），由 `tools/mkscf.py` 导出；补字仅使用 `tools/import_font.py`。
- 每字记录 276B，文件总长 `12 + 字数×276`；当前 36 字 = 9948B（M6 历史 27 字 = 7464B）。
- 内核开机 `fs_read("sys/font.scf")` → `gfx_font_load()` 激活为默认字体;
- 读不到文件则回落编译在内核里的内置表 —— **渲染器零改动**,
  这就是字体接口: 换字体 = 换盘上的文件。

## 3. SCX1MIO 可执行格式

```
偏移  大小  内容
0     8    魔数 "SCX1MIO\0"
8     4    entry   入口 RVA (相对装载基址)
12    4    load_size  装载字节数
16    4    bss_size    装载后清零的字节数
20    4    stack_size  建议栈大小
24    4    flags       bit0: 位置无关 (v1 未用)；bit1: 尾部SCB2图标
28    4    base        装载基址 (v1 固定 0x400000)
32    4    署名 "MIO\0"
36    ...  装载映像 (平二进制)
```

- 加载器: `task.c` 的 `task_exec_scx(path)` → 校验头、完整装载长度、入口、基址与栈大小
  → 私有页目录和用户页 → 清 bss → `task_spawn`。用户栈映射在用户区顶部，遵守头部建议长度。
- 汇编源码必须先由 NASM 生成机器码，再交给 mkscx；禁止把 `.asm` 文本直接封装为 SCX。
- 用户程序写法见 docs/SYSCALL.md §4。

## 3.5 桌面快捷方式与图标

`desk/*.lnk` 是 UTF-8 三行文本：显示名 / SCX 路径 / SCF 图标路径；支持 LF 或 CRLF，末行可有换行。
显示名限 11B，目标与图标路径限 30B。图标用 SCF1MIO 单字形 16×16；标签可为 ASCII，画布透明底。
默认 `desk/shell.lnk` → `bin/shell.scx`，图标 `sys/shell.scf`。图标像素独立于用户中文字库。

# M9 SandFS v5 扩展（集成与损坏边界验证进行中）

当前两个来源v5盘已实际运行读写/权限及目录提交边界。build/m9-fs-20261005-05
包含26次独立Windows QEMU、136个分项：非活动bank破坏、完整备用目录未切换、
完整超级块切换、坏超级块/活动bank CRC、正确CRC但条目保留位/rw/代数/UID非法、
重复名字、数据范围重叠、缺失父目录和虚假容量。前三类挂载后核对真实元数据及
正文SHA256；其余类通过COM1读内核卷状态确认拒绝挂载，HELLO无法启动Shell
且PUT_BEGIN返回无会话。原盘摘要不变，全部失败沿革保留。
这只是离线模拟提交落盘状态与结构破坏，不证明真实掉电、扇区撕裂原子性或
所有运行期I/O失败；后文早期“未验证”保留当时记录，不代表上述范围的当前状态。

历史v4及更早规范保留在上文。M9新发布盘为v5，旧卷兼容读取但三环写入前
必须迁移副本；不是在旧盘旁挂权限数据库。新输出格式2048项、96B项，两个
384扇区目录bank，数据从LBA769开始；所有父目录都有显式记录。

超级块沿用SANDFSMIO：12=count、16=384、20=5、24=盘扇区数、28=96、
32=root_uid、36=root_gid、40=root_rw、44=当前目录CRC32、48=bank(0/1)、
52=目录提交代数、56=持久对象序号、508=超级块前508B的CRC32。
bank0为LBA1..384，bank1为385..768。对象修改/建立/重命名/权限变化分配
全卷单调对象序号，耗尽拒绝回绕；删除后建立同名文件不能被旧打开句柄认成原对象。
目录项：name64/start4/size4/uid4/gid4/rw4/flags4/generation4/reserved4；
flags bit0为目录，其start/size均0，普通文件start>=769。rw六位分别为
owner r/w、group r/w、other r/w，默认23即三组均可读、仅所有者可写。
reserved必须0，代数非0，路径规范/去重/范围/父目录和数据区不重叠均挂载时校验。

写入采用磁盘位图找空闲连续范围，先写完整新数据和备用目录，最后切超级块；
成功后回收旧范围。删除同样先提交目录再释放旧范围，重命名失败保留内存旧表。
不因覆盖文件反复追加直至用尽盘。CRC用于损坏检测，不是签名或权限。
最后超级块提交I/O结果不明时卷转只读，不宣称恢复内存就等于磁盘回滚；实际
硬件掉电/扇区撕裂不承诺原子性，坏超级块CRC拒绝挂载。
