# SandFS 文件名填充污染修复

普通SCCC编译通过旧写入接口新建SCO、map和log；目录事务切换到复用物理页后，新记录名字尾部未初始化。原生目录序列化又把整个64B字段复制到盘上，导致CRC正确但文件名末字节非法，loader扫描目录和SandEditor均拒绝。源代码修正新文件/目录初始化及重命名名字清理，原生序列化只写逻辑字符串并补零；保持盘格式、ABI、严格读取检查和双bank提交顺序。

只做一次Windows QEMU / WHPX启动：修复副本正常进入主核，真实SYSTEM会话中SCCC生成SCO、SCLD链接，程序实际输出DIRFIX_OK。结束后通过qemu-img读取真实COW卷的超级块和两个目录bank，严格解析及全部名字零填充通过。没有重跑组件矩阵；运行使用小型COW覆盖层，修复副本保持原样，测试临时文件未进入用户盘。

用户盘先完整备份，仅清理19条文件名结束符之后的填充；2700个对象保留，更新主核及恢复主核。其余2698个对象的路径、完整正文、UID/GID、权限及对象代数逐项相同，根权限不变。test仍只有四文件，两个启动脚本和引导盘未改。备份与完整迁移凭证留在本地build/m10a2-directory-repair-01，不上传用户镜像。

`verification.json`为本轮实际命令和落盘检查结果；它只证明这条具体缺陷的修复范围，不宣称任意存储故障均已覆盖。旧M10a2.1发行包没有随此源码提交自动更新。

后续发行采用独立[M10a2.2补丁](../../docs/M10A2.2-RELEASE.md)：从干净M10a2.1发行盘换入相同修复主核和恢复主核，复用本次证据，不重复启动测试。原M10a2.1的Release及附件保持原样；打包内容与摘要见[发行凭证](../m10a2-directory-release/delivery.json)。
