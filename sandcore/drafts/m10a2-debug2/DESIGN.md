# Debug 2 实现草稿

2026-10-16。本目录是独立待整合实现，不代表构建或客体验收通过；旧 debugger.c、SCDBG.inc、scdbg.c、SCAPI.H 原字节保留。

## 对象与现场

公开头先定义 `SC32DEBUG.H`，库入口集中在 SC32API 的私有适配源。目标引用含 PID、进程代数和调试绑定代数，每次操作由内核重新检查真实 owner、owner 代数、UID 和 session。普通 root 不能借新接口获得外部 SYSTEM / Ring0 调试。启动沿用真实 streams 作业，在同一个 IF=0 陷入中建立 owner 并停在首指令前。

暂停现场发布带 `stop_generation` 的真实寄存器副本。读内存、修改断点、单步和继续必须提交同一暂停代数；运行、退出、槽复用或新暂停使旧请求失效。GUI 先构造包含反汇编、寄存器、内存、栈、模块、符号及断点的候选，最后复查现场后一次发布。运行时清除现场可用标志，标题明确显示运行，旧帧不冒充当前现场。单步由真实 x86 TF/#DB 实现；未知指令只消费一个真实字节并显示 db。

动态断点使用独立对象池与目标所有权链，不扩大旧八槽宏。INT3 命中恢复原字节、回退 EIP、TF 执行原指令，随后重插；退出、卸载、删除待恢复断点都撤销对应状态。旧接口继续支持其原八槽语义，两个入口不能争用同一地址。

## 模块与符号的正式来源

SCLDR ROOT 使用自己的 freestanding 私有登记桥，不依赖 SC32API。登记发生在重定位及保护完成、init 执行之前。内核独立读取真实来源文件、验证 SCL 格式、元数据、实际 MODULE 分配及段范围，并比对映像的原始内容与全部重定位结果。导入仅解析已经登记的同进程依赖，段 RW 位按真实页表核验。内核保存来源完整 SHA256、路径、ABI、映射/装载代数、段及导出符号快照；不是扫描目标的 SCLDR 私有堆。

SCX 主映像由可信加载路径直接登记文件 SHA256/大小和实际 load/BSS 范围。固定 ROOT 由可信 scl_boot 在首指令前直接登记，Adopt 只借用该真实内核记录，不把已运行 loader 的 BSS 错当成初始零字节。SCL 释放前撤登记，MODULEFREE、进程异常/退出与回收同步撤销。符号只有导航意义，不能授予读写权限。导出符号来自登记元数据；可选 `SCDB1MIO` v1 sidecar 必须完整 SHA256、文件尺寸、地址域、模块段均匹配才使用，保留 TU 本地符号及源行身份。

## 界面设计

统一 SCUI 控件树：菜单、工具栏、命令/目标输入、地址导航与状态栏；中部左侧主反汇编，右侧寄存器，下方内存/栈及 Modules/Symbols/Breakpoints 页签。水平和垂直 Splitter 可拖动，辅助区可浮动/重新停靠，并可恢复布局。表格全部使用 provider 可见区查询，不复制菜单或控件实现。Classic/Aurora 使用同一模型和布局，颜色只取 SC32 的既有主题角色。

代码、地址与字节统一 CODE 字体；说明用 DENSE；暂停、不可读和错误使用已登记主题角色。不以裸 RGB 或静态模拟数据绘制。空列表说明真实原因。隐藏 GUI 不采样/生成帧；目标独立运行，恢复可见后刷新一次。运行状态只以有预算的 SCUI 后台 timer 查询，不循环整帧重绘；关闭时实际停止独占目标、领取作业并释放窗口/模型/候选内存。
