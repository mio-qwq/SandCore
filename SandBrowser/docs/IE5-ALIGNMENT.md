# IE5 参照与功能对齐

作者：mio。记录日期：2026-10-20。状态：研究基线与构建记录；运行待用户验证。

## 参照依据

主要参照为 Windows 98 上的 Internet Explorer 5。微软 1999 年发布资料明确记载了搜索助手、地址自动搜索、自动完成、收藏夹整理和历史操作；这些能力需要有对应的实际用户流程。[微软 IE5 发布资料](https://news.microsoft.com/source/1999/03/18/microsoft-delivers-worlds-fastest-modern-browser-available-today)

同期微软资料还描述了友好的错误信息和建议、表单自动完成、完整网页的离线保存。相应目标包含可恢复的失败状态、输入体验，以及包含页面资源的保存行为。[微软同期产品说明](https://news.microsoft.com/source/1999/03/18/msn-announces-new-customized-version-of-internet-explorer-5free-download-available-at-msn-com/)

工具栏布局以微软公开的 IE 风格工具栏和 Explorer Bar 说明为结构参考。前一篇文档部分示意图来自 IE6，不能当成 IE5 的逐像素截图；其中对 IE5 起使用的列表式工具按钮有明确说明。[工具栏结构](https://learn.microsoft.com/en-us/windows/win32/controls/cc-faq-ietoolbar)、[Explorer Bar](https://learn.microsoft.com/en-us/windows/win32/shell/band-objects)

配置范围参考微软专门列出的 IE5/6 设置，包括主页、历史、图片、地址完成、缓存和安全相关选项。此资料用于核对能力，不要求模拟 Windows 注册表。[IE5/6 配置项](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-gppref/3fb5c89d-d9c2-41e2-9749-f5cac492121e)

## 视觉与交互合同

- 窗口内由菜单、标准工具栏、地址栏、可选链接栏、浏览区域和状态栏构成；侧栏与浏览区域之间有分隔条。
- 灰色面板、凹凸边框、明确的焦点框、克制的阴影、紧凑信息密度和有含义的小图标共同构成视觉语言。
- 图标由本项目制作；保留 SandCore 的原生窗口管理和输入机制。
- 以单文档浏览窗口为默认结构。新建窗口及其历史、加载、脚本状态相互独立。
- 常用动作具备一致的菜单、工具按钮和快捷键入口。禁用状态、正在加载状态和当前页面状态来自同一命令模型。
- 缩小窗口时提供明确的工具栏溢出或折行策略；不能遮住地址输入或把必要命令移出可达范围。
- 页面文字与界面文字、焦点、选区、滚动和错误提示分别有稳定的状态模型。

## JavaScript 的独立边界

用户允许对 JS 收敛范围，页面渲染目标保持复杂。本轮使用 Duktape 2.7.0，浏览器 DOM 绑定仍需客体验证，不能用“装入脚本引擎”代表浏览器脚本兼容完成。

优先形成以下通用闭环：变量和表达式、函数与条件/循环、对象与数组、字符串与基础数值；页面加载与点击/修改/提交事件；按 ID 获取元素；读取与更新正文、常见属性和样式；表单值和基础计时器。每一项都要列出精确接口、错误语义、生命周期和测试。

脚本任务必须有执行预算、异常报告与取消途径。导航后旧 DOM 引用、计时器和回调不得继续修改新页面。跨来源访问、脚本可见对象和本地文件访问具有明确边界。

ActiveX、VBScript、Java 插件、Windows COM 与系统邮件/打印集成依赖不同平台能力，需单列评估；当前没有实现或兼容承诺。现代框架、媒体、扩展和全部现代 Web API 不由“简单 JS”一词自动涵盖。

## 验收方法

测试组织以 URL/HTTP、HTML/DOM、CSS/布局、脚本语言、脚本绑定、输入/焦点、持久数据、安装和资源生命周期为轴。包含正常路径、反例、畸形数据、重入/取消、内存失败和磁盘错误。

渲染对照页覆盖布局结构、编码、图片、表格和表单的组合，避免只测试一张欢迎页。跨站抽样补充公开测试，不代替通用规则测试。抽样网站不成为代码中的白名单或专用修复分支。

进度记录使用“待实现、已构建、宿主测试通过、客体实测通过、存在缺口”等明确状态；每个通过项关联实际产物和结果。当前只有编译、链接及容器校验结果，没有客体功能通过声明。
