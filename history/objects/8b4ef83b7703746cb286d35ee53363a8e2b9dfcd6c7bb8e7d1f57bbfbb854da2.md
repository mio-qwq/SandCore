# SandCore M9 当前测试版

双击上一层的 `run-m9.bat`。它使用本机 Windows QEMU 和 Python，显示桌面窗口，声音走 DirectSound；旁边的控制台是模拟另一台机器连接的外部双串口工具。

这份快照已构建，已有客体执行证据，但完整 M9 双盘、边界、兼容和性能验收仍在进行。Shell 使用原来的 Aurora / Classic 图标。不会自动跟随后续开发修改。

桌面窗口中可以启动 Shell、Sound 等应用、切换主题。串口控制台默认是外部 SYSTEM 管理 Shell；普通命令直接输入，例如 `help`、`ls /SYS/TEST`、`sccc /SYS/TEST/ONCE.C /SYS/MOD/TEST.SKM --skm`。

宿主控制台专用命令：

- `:raw`：逐键终端，用于 nano / SCDBG；按 Ctrl+] 回到宿主菜单。
- `:put "C:/本机/文件.C" /TMP/FILE.C`：传入文件。
- `:get /TMP/FILE.BMP "C:/本机/新文件.bmp"`：取回文件，目标必须尚不存在。
- `:debug` / `:management`：切换 COM1 零环调试 / COM2 管理 Shell。COM1 可输入 `hello`、`halt`、`regs`、`step`、`cont`。
- `:quit`：退出本次试玩。不要把它当成客体的普通 Shell 命令。

每次启动产生独立的 `sessions/日期时间/`。数据盘、串口记录和 QEMU 日志保存在这里；默认从最近一个已成功启动的试玩盘继续，因此文件修改可以保留。`images/` 中随包基线不写入。想重新开始可在命令行运行 `run-m9.bat --fresh`，旧会话仍保留。

如果数据盘坏了、管理 Shell 起不来，可以运行 `run-m9.bat --debug-only`。这次只用独立 COM1，等内核串口就绪后可输入 `hello`、`halt`、`regs`、`mem 地址 十六进制长度`、`cont`；不创建 COM2 SYSTEM Shell，也不传文件。修好后按默认方式重启。此工具模式已在坏超级块的真实 QEMU 上通过。

`images/kernel.sym` 对应此快照，供外部调试定位；测试夹具在客体 `/SYS/TEST`。本目录不含已安装的 QEMU、Python、GCC 本体。系统引入的第三方源码、版权与完整许可在客体 `/SYS/LICENSE/`；随包 `docs/THIRD-PARTY.md` 记录来源和许可选择。

开发中另修了 Shell 简单参数强制带引号，导致一些旧 GUI/旧 M7 程序认不到参数的问题。修复版本已在两个来源盘各通过 112 个集成分项，放在 `updates/shell-20261005/`；未自动改你的试玩盘。要用它，在外部串口控制台输入下面命令，然后 `:quit` 并重新双击启动，文件修改仍保留：

