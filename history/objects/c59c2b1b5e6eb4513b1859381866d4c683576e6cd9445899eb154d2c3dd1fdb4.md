# SandCore 中断子系统规范 v0.4（M1 + M6）

> 定义 IDT 布局、PIC 重映射、时钟与键盘驱动的全部自定义约定。
> 对应实现: `kernel/idt.asm`、`kernel/interrupts.c`、`kernel/timer.c`、`kernel/keyboard.c`。

## 1. 向量号地图

| 向量 | 归属 | 处理路径 |
|---:|---|---|
| 0 – 31 | CPU 异常（除0、缺页、GP……） | `isr_common` 桩 → `isr_c_common()` → CPL0 panic；CPL3 注册回调或暂停卡片 |
| 32 – 47 | 硬件 IRQ（8259A PIC 重映射后） | `irq_common` 桩 → `irq_c_common()` → 驱动分发表 |
| 0x7C | **SandCall 系统调用** | DPL=3 的 0xEE 门，已启用；功能表见 SYSCALL.md |

**为什么重映射到 32**：PIC 出厂把 IRQ0-7 映射到向量 0x08-0x0F，和 CPU 异常
撞车（IRQ0 会踩"除零异常"的门）。初始化时用 ICW2 把主片搬到 32、从片搬到 40。

## 2. IDT 布局

- 125 个门（0..124），每门 8 字节：`offset_lo:16 | selector:16 | rsv:8 | attr:8 | offset_hi:16`
- selector 恒 `0x08`（内核代码段）；attr 恒 `0x8E`（在场 P=1，DPL=0，32 位中断门）
- 中断门进门自动 `cli`，`iretd` 恢复 EFLAGS 自动还原 IF —— 桩里无需手动管中断开关
- M5 加系统调用门时：attr 用 `0xEE`（P=1，DPL=3，允许用户态触发）

### 桩的栈帧约定（idt.asm 文件头也有同款图）

```
低地址  ┌───────────┐
  ESP+0 │ GS/FS/ES/DS │  公共桩压入 (每 4 字节)
        ├───────────┤
  ESP+16│ pusha 8 寄存器│  EDI..EAX
        ├───────────┤
  ESP+48│ 向量号      │  桩压入
  ESP+52│ 错误码/补0   │  CPU 压或桩补 0 —— 两类桩在此对齐!
        ├───────────┤
  ESP+56│ EIP/CS/EFLAGS│  CPU 压入
高地址  └───────────┘
```

C 异常/系统调用分发器接收完整帧。ring3 额外在 +68/+72 保存 ESP/SS；初始用户现场的四个数据段为 0x23，CS=0x1B。
IRQ 出口执行 `sched_pick`，切换 ESP、CR3 和 TSS.esp0；系统调用出口通过 `syscall_finish` 原路返回普通调用，只对 EXIT 立即调度。

## 3. IRQ 分发表（interrupts.c）

```c
static void (*irq_handlers[16])(void) = {
    [0]  = timer_tick,     /* IRQ0  PIT 时钟 */
    [1]  = keyboard_isr,   /* IRQ1  PS/2 键盘 */
    [12] = mouse_isr,      /* IRQ12 PS/2 鼠标 */
};
```

新驱动一律在自己的模块里实现 `xxx_isr(void)`，然后到这张表登记，**不改公共路径**。
M4 已认领 IRQ12：鼠标（docs/WM.md §1 有完整协议）。

**EOI 纪律**：`irq_c_common` 处理完必发 EOI（从片 IRQ 还要主从各发一次）。
漏发 EOI 的症状：同级别中断永远不再到来。

**当前放行的 IRQ**：0（时钟）、1（键盘）、2（级联）、12（鼠标），其余全屏蔽。

## 4.5 PS/2 鼠标（IRQ12，M4）

- 初始化四步：`0xA8` 开辅助口 → 改控制器配置（bit1 放行鼠标中断、bit5 恢复时钟）
  → 经 `0xD4` 发 `F6`（默认值）→ 发 `F4`（开始上报）；ACK 用 suppress 标志压掉；
- 三字节包：B0 = 按键(bit0/1/2) + 同步位(bit3 恒 1) + 符号位(bit4/5) + 溢出(bit6/7)，
  B1 = X 位移，B2 = Y 位移（屏幕 y 取反）；
- 同步：B0 bit3≠1 即字节错位，丢字节重对齐；溢出帧作废；
- 光标状态由驱动维护，WM 每轮主循环轮询（docs/WM.md §1）。

## 4. PIT 时钟（IRQ0）

- 8253/8254 通道 0，模式 3（方波），输入基频 **1193182 Hz**
- 目标频率 100 Hz → 除数 11931（实际 100.0075 Hz，误差忽略）
- `sc_ticks`（volatile u32）每 IRQ0 加一，全系统唯一时间源
- 约定：`sc_ticks / 100` = 秒；显示层只取 0.1s 粒度（百分位跳动晃眼）
- u32 在 100Hz 下 497 天溢出 —— 内核寿命内不管，桌面时钟 M6 再封装

## 5. PS/2 键盘（IRQ1）

端口：状态 `0x64`（bit0=输出缓冲满），数据 `0x60`。

### 扫描码约定（码集 1）

| 码 | 含义 | 码 | 含义 |
|---|---|---|---|
| 0x2A / 0x36 | 左/右 Shift 按下 | 0xAA / 0xB6 | 左/右 Shift 松开 |
| 0x3A | CapsLock 翻转 | 0xE0 / 0xE1 | 扩展码前缀（方向键等，M4） |
| 通码 & 0x80 ≠ 0 | 断码（松开），忽略 | 其余 | 查映射表转 ASCII |

- 映射表 `map_base[0x80]` / `map_shift[0x80]`：下标=通码，值为 ASCII；0 = 不产键
- 字母键大小写 = `Shift XOR CapsLock`
- 返回给上层的字符集：可打印 ASCII（32..126）、`'\n'`(Enter)、`'\b'`(退格)、`27`(Esc)
- 驱动队列：M8扩至128字节环形缓冲（127有效），ASCII/扩展/功能事件都入队，满则丢新键。
- 用户窗口另有16槽队列（15有效）；M8由任务0在短临界区路由聚焦窗口，ISR不再执行菜单/SCX加载。
  F2/F3/F5=2/3/5，方向键E0上/下/左/右=0x80..0x83；非阻塞key_pop按无符号0..255返回，空为-1。
  完整用户事件表见SYSCALL.md；KEYDOWN的物理按住状态仍由ISR立即维护。
  窗口队列满时路由返回0，任务0保留驱动队首、恢复抢占给应用消费，下一轮重试。
  因此批量转送不会截断Shell/SCCC长命令；keyboard_overflow单独记录驱动队满丢字。

### 上层 API

```c
int getkey(void);   /* 阻塞: 空队列时 hlt 睡眠, 中断唤醒后重查 */
int kbhit(void);    /* 非阻塞探测 */
```

## 6. panic 红屏

内核 CPL0 异常 → `panic(reason, vec)` → 关中断 → 整屏 PAL_PANIC 红 +
黑字三行（标题 / 原因 / `VEC 0xNN`）→ `hlt` 死循环。设计立场：**内核 bug
必须壮观地死，绝不带病运行**。

### M7 异常与单步（2026-10-02）

CS.RPL 来自 CPU 现场：CPL0 错误仍 panic；CPL3 未处理异常暂停目标任务，
弹出卡片，关闭才杀掉并回收。异常处理器用独立用户栈接收 19 双字现场，
EXCRETURN 只恢复通用寄存器/EIP/ESP/普通标志，禁止提升 CPL/IOPL 或关闭 IF。
回调再次出错不递归。INT3 门也开放 DPL3；调试器使用真实 0xCC 与 EFLAGS.TF。
命中先退 EIP/恢复原字节，执行原指令后重插断点，单步不会漏掉被替换的指令。
F1..F10=1..10，方向键/ASCII 新增按下与松开状态；KEYDOWN 还需焦点资格。

2026-10-02：修正高功能键事件与编辑控制字符冲突。F1..F7=1..7；F8/F9/F10=0x88/0x89/0x8A；Backspace=8、Tab=9、Enter=10，不能混用。

### M8 大屏合成与硬件接收（2026-10-02）

整帧真彩色合成不能长时间cli：8042字节FIFO有限，按下/松开可能丢失，PIT也会漏计。
任务0短临界区处理显示/键鼠队列和窗口结构；绘图时设置内部render_hold后开中断。
IRQ驱动和EOI照常运行，sched_pick在hold期间返回本现场，暂不切三环或回收僵尸。
因此画布生命周期稳定，但硬件能持续上报；结束先cli解除hold，再恢复普通抢占。
键盘ISR只入队，不能重入菜单EXEC/窗口操作。这个内部入口不向用户态开放。

鼠标驱动缓存63个有效事件，连续同按钮移动合并为最新坐标，按钮边沿独立保留。
任务0依次命中每个事件；队满丢最旧并累加event_overflow，验收要求零溢出。
键鼠ISR检查状态口AUX来源位，不能互相吃掉另一设备的字节。VGA路径也走同一事件队列。

2026-10-02：M8合成期间持续IRQ接收/延缓切任务、128字节键盘队列/鼠标边沿队列
和8042来源检查同步；完整M8功能仍需后续验收。

2026-10-02：窗口队列背压与key_peek登记，128槽驱动不能一次倾入15有效窗口槽
并丢尾字；长参数通过EXEC/GETARGS实际核对，验收要求键鼠两个overflow计数均为0。

2026-10-03：IRQ公共C入口额外接收原CPU现场指针，汇编压ESP再压vec，
返回回收8B参数，已发布陷入现场布局不变。IRQ0在tick/调度前按现场
CS.RPL采样CPU分类，不能用ISR自身零环CS误算用户代码。方法、
IF=0采样局限和64字新快照见CPU.md，旧MONITOR 48字不改。

### M8 大帧复制的IRQ与生命周期（2026-10-03）

FRAME/FRAME32先在IF=0完成完整用户映射、owner、画布格式及精确
长度校验，然后设置内部render_hold=当前pid+1并STI。IRQ驱动、
计时和EOI继续；sched_pick匹配持有者时原路恢复，暂不切任务/
CR3或回收。主循环不能关闭/resize/换模式/合成半帧，其它三环
不能更改源映射。复制结束先CLI，再解除持有并发布alpha/dirty。
错误调用不写画布且不进入长复制。旧功能号/参数/返回/像素不变。

此前hold只保护任务0，不能把STI直接放入三环系统调用：下一次
IRQ会切到能释放画布的任务。新内部编码区分无持有0和任务0的1，
并保持任务/窗口公共结构原步长；没有用户态禁抢占入口。CLI/STI
还增加编译器memory屏障，约束持有者/共享数据在临界区正确一侧。
不嵌套获取，不在持有中YIELD，返回分发器时仍IF=0。

render_copy_ticks为只读私有诊断，记录真实PIT打断三环任务内核
复制；该执行分类仍是CPUINFO的kernel，原graphics只统计任务0
合成。验证tools/verify_frame_irq.py实际G2编译同一探针，1080p
大ARGB/索引帧、输入/原字节/中途X关闭回收与旧核对照已PASS，
复制内实际PIT110/12个，CPU kernel减graphics恰为对应复制样本。
证据build/m8-frame-irq/irq-enabled/results.json；100Hz精度与
源码/核摘要见PERFORMANCE.md。磁盘PIO等全部长IF=0尚未消除。

### M8 任务0空闲量子的主动让出（2026-10-03）

任务0完成本轮事件/计时/合成后，在IF=0检查旁表：存在可运行且
本tick未主动YIELD的三环，才通过原int 0x7C/YIELD汇编出口换栈。
恢复时仍IF=0，立即回主循环顶检查事件，不先HLT。无忙任务时
保持STI/HLT；用户YIELD本tick记录用于保留旧轮询程序的空闲节流。
旁表在初始化/任务槽复用时重置，不改任务168B或中断现场布局。
持有整帧render_hold时禁止走此路径，PIT/其他IRQ与原轮转不改。
功能号、忽略寄存器、YIELD返回0/仍可运行/主动轮转合同保持；
同一G2探针实测用户样本48.5%→97%、实际计算吞吐中位2.74倍，
旧YIELD待机93%空闲、双忙任务持续前进、键鼠/关闭/回收通过。
PERFORMANCE.md记录范围与精确核摘要，GUI/历史组件回归另存，
不把纯计算测试称完整M8或全部界面稳定帧率。
