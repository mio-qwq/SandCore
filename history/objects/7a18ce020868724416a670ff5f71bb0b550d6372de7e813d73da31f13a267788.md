> 每完成一个里程碑，这里会追加该里程碑的**手工自测指南**。

> 所有命令都在 `sandcore/` 目录下执行；Windows QEMU **必须双盘（引导 if=floppy + 数据 if=ide）**。

## 通用操作

```sh

# 玩

# 无头自动化验证 (可选)
```

进系统后：开机画面按**任意键** → 桌面与文件图标出现，**不自动开 Shell**。

### 自动化具体怎么验证（mio，2026-10-03）

自动化的操作对象是真正启动的SandCore。测试脚本负责准备副本盘、
发送键鼠、读取结果与判定；应用仍由系统的Shell/菜单执行，编译仍
由客体三环编译器完成。测试没有操作用户正在使用的QEMU。

1. **先固定输入，再启动双盘**。保存本批源码、内核、启动软盘、
   数据盘、SCAPI.H、字体及测试规则的SHA256；从开发盘复制独立
   测试盘，在开机前放入测试数据。Windows QEMU使用
   `-drive format=raw,if=floppy,file=build/sandcore.img`与
   `-drive format=raw,if=ide,file=本批副本.img`，另加`-display none`、
   HMP 4444/QMP 4445；每轮实际命令保存在`qemu-*.json`。已有端口
   被占用就拒绝启动，不能接管别人的虚拟机；多轮必须串行。
2. **真正编译、真正运行**。涉及原生应用时，从已验收M7 ZIP取出
   精确历史G2，在客体执行例如
   `run BIN/G2.SCX SYS/SRC/debugger.c HOME/DBG.SCX`。实际生成的
   SCX、map、编译日志和命令留在本批目录，再通过Shell执行该SCX。
   宿主语法检查、宿主生成的默认程序、测试源文件存在，都不能
   代替这一步。辅助算法探针同样由真正G2生成普通三环程序；它
   验证对应函数的边界，不能冒充完整GUI的鼠标测试。
3. **输入走设备协议**。键盘由HMP `sendkey`，鼠标由QMP
   `input-send-event`发送相对移动、按下、释放。由真实窗口几何
   定位按钮，而不是直接修改应用选中项；测试打开/保存/右键/
   翻页/滚动/拖动/调整大小/最小化/最大化/还原等实际路径。排队
   首字专测另读取主循环调用链和窗口键队列，必须证明字已在
   外层动作决定前排队，不能用输入框打开后的普通打字冒充。
4. **截图与真实数据都核对**。HMP `screendump`导出实际显示器
   画面，再转换PNG供视觉审阅。用`stop/pmemsave/cont`取得只读
   快照，按真实PDE/PTE读取应用虚址；不写客体内存、寄存器或
   任务状态，也不直接调用客体函数。图形测试比较完整私有帧/
   窗口画布，合成专测继续比较后台/PCI像素；这些检查分别注明
   覆盖范围。调试器现场则与内核saved_esp原帧核对，栈只比较
   已完整映射的4B槽，未映射必须显示????????。
5. **测试矩阵、失败与退出**。适配批次覆盖五档分辨率×三档缩放、
   三组Classic以及VGA回退，并保留各组合独立结果。文件失败/
   超长输入/缺页/分配OOM/任务复用等边界另测；关闭后等待实际
   任务回收和Shell提示符恢复，检查物理页计数及队列溢出，
   不能把合法调试暂停当普通异常，也不能只看窗口已消失。
6. **性能与结论分开记录**。计算吞吐或完整draw+FRAME32成本用
   客体PIT计数、同一程序和多轮对照；输入延迟报告包含宿主
   自动化观察开销，记录中位数/P95及测量下限。暂停读取会影响
   时序，不能把诊断快照或计算吞吐直接说成显示器帧率/全部
   GUI丝滑。成功才写PASS，失败资料原样转入history后重新跑；
   源码或产物改变必须重测，不套用旧摘要的截图与报告。

每项结果都要看`results.json`的输入摘要、checks和limits。
例如本轮新调试器核心在`build/m8-debugger-draft/results.json`，
21项解码在其`decode/results.json`，退出/PID复用在
`lifecycle/results.json`；首字、十九布局、正式预装联合回归
必须各有自己的成功报告。准备好了脚本、单个阶段PASS和整个
M8完成是不同状态，完整里程碑仍以最终验收包与用户验收为准。

2026-10-03本轮补测：新调试器`action-queue/results.json`也已
完整PASS；1920/100实际主循环draw中的队首4，与后续00010组成
00400010，完整目标128B、真实Esc退出/专属目标回收/原Shell
提示符、严格物理页数及零队列溢出均通过。新的十九布局正在
串行执行，须读取其最终报告，不能按已启动就宣称全矩阵通过。

### F. 文件管理器与核心保护

run apps/files.scx HOME，N 输入 HOME/PLAY 回车创建空目录；选择它
Enter，进入应为空；Backspace 回 HOME。F2 输入新的完整路径重命名或
移动，X 后 Y 确认删除；非空目录会失败。F5 刷新，j/k 或上下选择。

到 SYS/CORE，尝试改 CORE.SKM 应显示 Core path protected by kernel；
直接系统调用也返回 -5。保护不只是一项文件管理器按钮限制。
SYS/MOD 是自定义零环模块目录：SKM 格式与风险边界见 MODULE.md；
它们开机执行零环代码，有完整内核权限，格式合法不等于代码安全。
