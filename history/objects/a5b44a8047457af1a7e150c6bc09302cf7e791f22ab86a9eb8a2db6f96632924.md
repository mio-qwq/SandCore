## 2. 身份与物理串口边界

SYSTEM 是开机创建的系统身份，负责启动用户态服务。其凭据/票据及每次启动的
随机令牌留在内核，普通登录、图形登录和网络登录不提供获取 SYSTEM 的入口。
未来 SSH 最高只能获得 root。权限边界是运行 SandCore 的被调试机：真实硬件上
只有另一台机器从外部物理串口连接，才能取得这条硬件管理路径。在当前 QEMU 环境，
客体是被调试机，宿主工具扮演另一台调试机，QEMU 模拟 UART 和外部串口连接；
即使两者在同一台现实电脑上运行，也只把客体外部接入视为等价硬件 access。
“串口”不是允许任意系统内虚拟端点、网络转发或进程自连取得最高权限。

每个进程在创建时绑定调用者身份。切换用户不重新标记已经存在的进程；执行文件的
所有者也不改变调用者身份。内核校验用户切换、认证和票据，不信任三环寄存器、
环境变量或用户可写文件中的自报 UID。异步请求必须同时绑定创建者及任务代数，
防止退出、PID 复用或重新登录时继承旧授权。

SYSTEM 服务身份与外部串口管理授权必须区分：开机运行的普通 SYSTEM 服务，
不能仅凭 UID -1 就获得 /SYS/MOD 编辑入口或任意零环执行入口。串口授权由内核
记录其来源和生命周期；创建子进程时只能在明确受控的管理链路中继承。

**客体不能连接自己的管理串口是硬边界。** 普通用户/root 不得取得原始 UART、
I/O 端口、设备映射、回环控制、接收队列注入或伪造管理会话来源的能力。
内核接收入口只认硬件 RX；不得把可写软件队列、普通管道、网络转发当成外部 RX。
管理串口可读写端点不通过普通文件打开接口发布。CPU 的 IOPL、TSS I/O 权限以及
异常返回现场须始终保持三环不能自行取得原始 I/O 权限。

宿主启动配置同时属于边界：管理串口与 QMP/HMP 不使用可被客体访问的 TCP 后端。
M9 关闭客体网络设备；宿主工具使用本机通道并限制访问。在 M10 加入网络时必须
重新验证宿主网关、端口转发、共享设备和串口后端均不能成为取得 SYSTEM 的通路。
已由外部串口 SYSTEM 明确授权的零环代码属于最高信任代码，能够访问内核；
不声称用三环权限隔离这类代码，也不因此向 root 开放零环能力。

## 3. rw 权限与 SandFS

文件 r 决定读取与加载/执行 SCX；w 决定修改内容。不存在独立执行位，因而允许
读取的程序也允许以调用者身份运行。目录 r 决定列举与通过目录访问后代；目录 w
决定新建、删除、重命名子项。修改已有文件内容仍另外检查该文件 w。

root 绕过普通文件/目录权限；内核保护目录不受此绕过。/SYS/MOD 的串口管理
限制与已有 /SYS/CORE 内核保护单独检查，路径先统一规范化、大小写折叠和处理
点段，再检查目标及移动源、祖先目录。不得用权限六位代替特权路径保护。

旧 SCAPI 函数号、寄存器含义、返回值和缓冲布局保留；权限执行属于新身份模型，
新增元数据查询、改权限和用户管理使用新调用，不偷偷扩展旧缓冲。
新磁盘格式及迁移工具在 FS.md 中独立标版本。迁移先生成副本、验证全文件内容
和元数据，再由开发启动器使用；不覆盖 M8a、M7 或用户试玩盘。
历史无显式目录的前缀投影须在迁移时形成可检查的目录权限链。

SCX 现有 36B 头不改：offset 24 flags 的 bit0 是历史保留、bit1 是 SCB2 图标，
bits2..31 尚未分配且旧加载器拒绝。不能用新 flag 赋予执行者 SYSTEM 身份。

## 4. Shell、CLI 与原生编译

Shell 同时服务图形终端与串口终端，命令执行不依赖先创建窗口。
完善参数/引号、变量、返回码、脚本、重定向、管道、同步等待、后台任务及信号/
取消路径；输出为真正字节流，二进制文件与 stderr 不混入提示符或传输控制信息。
文件、文本、进程、身份、存储、诊断、归档/校验等命令分别产出独立 SCX。
可共享自写内部辅助代码，但不能把相同 multicall 程序复制成多个文件冒充独立实现。

BusyBox 只作为行为和覆盖对照。冻结参考清单后逐项记录实现范围、选项、组合行为、
实际验证与缺失项；联网命令记为 M10，仍在总清单中列出，不静默缩小分母。
没有运行证据的命令不计覆盖率，空壳、仅打印帮助、永远返回成功不计完成。
若网络/其他平台专有项与约 80% 总目标出现实际冲突，先提交覆盖统计让用户取舍，
不得自行下调目标。本轮不把标准 C 运行库作为 CLI 工作的隐含前置目标。

2026-10-05统一构建前的工程适用性记录：按本轮已经确定的SandFS/UID/rw/
外部串口/单CPU/网络留M10边界，原310行额外标本地171、网络55、平台专有82、
用户明确排除2（vi/热卸载）。这是可复核的工程分类，不把平台缺项写成PASS，
也不声称用户批准了新覆盖率分母。此前口径问题未获新答复，暂以本地能力
推进可运行验证；原始总表、缺失状态与全部计数仍保留，最终提交两种口径
和实际行为证据供验收。140个本地参考名有源码（总表45.2%，本地81.9%），
仅说明约80%本地范围已有实现入口，任何行为覆盖率仍为未验证，目标未宣布达成。

SCCC 纯命令行版可用参数指定源、输出及诊断，失败保留已有产物；编译、include、
诊断和打包核心与 GUI 版共享，CLI 入口不创建窗口。原生零环打包覆盖真实重定位、
BSS、入口及格式校验，不把 SCX 改扩展名伪装成 SKM。

2026-10-05用户明确编辑器选nano而不要vi。旧ed/GUI编辑器/历史产物保留；
BusyBox参考表vi行标USER-EXCLUDED，不删除或把nano算作vi行为通过。
M9的bin/s3c.scx与bin/sccc.scx都是编译器CLI命令名，旧GUI核心源码保留；
bin/scdbg.scx为三环调试CLI，bin/debug.scx为兼容命令名，不计作两个独立功能。

## 5. SSE2 与复杂组件编译

M9 自研工具链新增范围为 SSE2 整数向量，不由此自动扩为 C float/double 语言支持。
按 CPU 能力检测，建立每任务扩展状态的初始化、抢占保存/恢复、异常恢复、退出及
槽复用清理；覆盖 XMM/MXCSR，兼顾宿主编译复杂三环组件可能使用的 x87 状态。
提供无 SSE2 回退，禁止跨任务泄露寄存器内容。内核业务代码继续禁浮点/libc。

用户已作一般授权：以后过难的组件允许宿主编译，MP3 解码核心也允许；宿主编译
产物仍须在 SandCore 原生执行，记录源码、工具链和实际依赖，不能以宿主执行冒充。
SCCC 自举与系统内编写/编译 CLI 的目标继续保留，不把一般授权当成停止完善原生工具链。

MP3 可采用成熟自由开源解码核心；只选择宽松许可，随发布保留许可证与必要版权
声明。dr_mp3 的 MIT-0 是候选，最终版本、源码摘要、许可证和依赖在实际引入时记录。
音频驱动、服务、系统音效策略和播放器由项目实现；解码在三环，驱动不引入 libc/
浮点。优先流式读取与有界 PCM 缓冲，支持系统提示音与播放器并存、音量和静音，
正常关机在结束音效后退出，硬复位/断电不承诺完整播放。

## 6. 指定窗口截图与开发闭环

截图工具按窗口句柄及代数捕获已完成提交的窗口内容。指定窗口不依赖它正好位于
桌面最前；窗口关闭、尺寸变化、任务退出与槽复用有明确失败/快照处理。
普通用户不能借截图读取别人的窗口，root 按普通身份管理权限处理；SYSTEM 管理
工具以受控授权工作。像素尺寸、格式、全窗口/客户区约定使用新接口及版本，
不改变旧 WININFO/FRAME 返回布局。

完整验收链：本机工具连接串口 → 系统内编辑源码 → SCCC CLI 编译 → 启动 CLI/
GUI → 三环或零环调试 → 指定窗口截图保存 → 串口下载 → 本机查看真实截图。
HMP screendump 用于验收取证，不能替代用户可调用的客体窗口截图能力。

## 7. M10 收敛

网络、中文/输入法、浏览器、CORE 签名与 SMP 留在 M10 路线。
**M10 完成时冻结基础内核**，不是 M10 开始时。M9/M10 可以补齐、验证必要的
模块接口与底座；冻结后基础内核只做安全更新，新增底层功能通过发布
/SYS/CORE/*.SKM 提供。该决定比原路线图的“尽量减少修改内核”更严格。

冻结前需核对模块发现/版本/依赖、受控注册、系统调用扩展、驱动/中断接入、
资源归属及可信更新入口，保留旧服务表前缀和旧三环 ABI。M9 不提供热卸载；
签名与 SMP 设计不能假装已由当前只含绘图回调的 SKM 服务表满足。

## 8. 实现顺序与验收

1. 独立 M9 输出、双 UART 与宿主连接底座；仅硬件传输，不先开放无保护 SYSTEM Shell。
2. 内核身份/可信会话、SandFS 新格式与迁移、保护目录及全部文件/执行路径检查。
3. 无窗口终端/字节流、Shell/独立 CLI、SCCC CLI 与原生零环打包。
4. 真正 Ring0 调试、双向文件传输及窗口截图，形成宿主可自动操作的完整闭环。
5. 扩展状态/SSE2 工具链、QEMU 声卡与音频服务、系统音效及 MP3/WAV 播放器。
6. Windows 无头 QEMU 双盘、GUI/串口组合、历史软件 ABI、坏输入/权限/回收、
   性能与故障矩阵；交付实际截图、音频记录、变更清单与验收说明。

目标门槛：root 不能写 MOD/不能取得 SYSTEM/不能访问原始 UART；旧进程身份
固定；两串口独立；暂停内核时调试通道不依赖普通调度；传输损坏/截断不发布半文件；
一次性零环代码正常返回后资源回收；常驻保持到重启；跨任务 XMM/x87 不泄露；
CLI 管道能处理二进制；指定窗口截图及串口取回内容一致；声音流结束/退出回收；
旧 SCX/SCAPI/LEGACY 保持兼容。性能分别记录客体 tick、宿主 CPU 和真实延迟，
不把传输夹具通过当成整个 M9 或 80% CLI 达标。
