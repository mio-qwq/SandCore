# SandCore 内存管理规范 v0.3（M2 + M6 分页）

> 对应实现：`kernel/memory.c`（E820 解析 + PF-Bitmap 物理页分配器）与
> `kernel/heap.c`（SC-Heap 内核堆）。两层职责分离：**页分配器管 4KB 物理帧，
> 堆管字节级小块**，后者从前者的领地里划地。

## 1. 物理内存版图（M2 历史快照，M6 见 §5.5）

```
0x00000-0x003FF  IVT（引导期后作废）
0x00400-0x004FF  BDA
0x00500-0x07BFF  自由（传统空闲）
0x07C00-0x07DFF  引导器
0x07E00-0x08107  E820 内存图（BOOT.md §4.5 契约）
0x09000-0x0FFFF  自由
0x10000-0x12F39  内核镜像（.text/.rodata/.data，文件尾对齐 4K）
0x12F3A-0x15220  内核 .bss（IDT、位图、行缓冲……entry.asm 清零）
0x15220-0x1FFFF  自由
0x20000-0x8FFFF  自由（含引导栈 0x90000 向下）
0x90000-0x9FBFF  引导/内核栈（顶 0x90000 向下生长）
0x9FC00-0x9FFFF  EBDA（BIOS 保留）
0xA0000-0xAF9FF  VGA 显存 (13h)
0xF0000-0xFFFFF  BIOS ROM
0x200000-顶      ★ PF-Bitmap 分配器管辖范围
```

2MB 以下一律视为"内核保留"不参与分配——牺牲 2MB 换取零特判，M5 分页
上线时这块地还能再规划。

## 2. E820 解析规则（memory.c）

1. 条数/条目按 BOOT.md §4.5 从 0x7E00 读取；
2. 只统计 `type==1(usable)` 且**完全在 4GB 内**的条目（32 位世界不记账高区）；
3. 取**包含 0x200000 的那条**的上界为管辖终点——QEMU 的低区 RAM 是一整块
   连续可用区，这个假设在我们成立；上界再与 256MB 封顶取小；
4. 管辖帧数 = (上界 − 2MB) / 4096。QEMU 默认 128MB 时 = 31,616 帧。

## 3. PF-Bitmap v1 物理页分配器

| 项 | 值 |
|---|---|
| 页粒度 | 4KB |
| 位图本体 | 内核 .bss，8KB（支持满编 256MB），entry.asm 开机清零即"全空闲" |
| 分配 | 从位 0 起 first-fit 找 0 位，置 1，返回物理地址 |
| 释放 | 清位（地址越界帧直接无视，不归我管） |
| API | `pframe_alloc() / pframe_free(addr)` |

设计取舍：first-fit 位图慢于伙伴系统但实现 100 行内、零隐藏行为；
缺页/换页等花活全部不存在——这就是 v1 的全部，也是它的美德。

## 4. SC-Heap v1 内核堆（heap.c）

| 项 | 值 |
|---|---|
| 堆区 | 启动时从 PF 分配器连续征用 256 帧 = 1MB（first-fit 下天然落在 2MB 起） |
| 尺寸级 | 8 级：16/32/64/128/256/512/1024/2048 字节 |
| 块头 | 4 字节：bit7=在用，bit7:0 低 7 位=级号 |
| 分配 | 本级空闲链头 → 摘取；链空 → 从区尾顺切新块 |
| 释放 | 头插回本级空闲链（next 指针借用块体前 4 字节，零元数据） |
| 上限 | 单块 ≤2048B；要大块请 `pframe_alloc` 整页 |

**v1 已知取舍（刻意为之，不是欠账）**：
- 不合并相邻自由块——碎片会慢慢碎，M5 升级时加合并；
- `kfree` 不校验指针合法性（块头级号越界即无视），调用方自律；
- 堆依赖"启动顺序"：`heap_init()` 必须是第一个物理页用户，才能保证
  1MB 连续。文档与代码共同背书这条约定。

## 5. 展示层

shell 的 `mem` 命令 = 本文档的运行时投影：E820 原始条目（MB 粒度）、
PF 分配器三数（managed/used/free）、SC-Heap 三数（total/used/blocks）。
改动任一分配器行为，`mem` 的输出语义必须跟着对。

## 5.5 M6 分页与生命周期

内核页目录位于对齐后的 BSS；1024 张共享页表占物理 3MB-7MB，恒等映射 4GB，main.c 在分配用户页前预留 3MB-8MB。
任务 0 使用内核页目录；用户任务拷贝共享项，私有 PT#1 覆盖 0x400000-0x7FFFFF，映射带 US/RW。
其他映射均为 supervisor，ring3 不能访问内核。系统调用沿用调用者页目录；无需假定用户物理页连续。
用户映像与 BSS 映射在 0x400000 起，栈在用户区顶部，内核栈独占一页。CR0.PG 与 CR3 必须实际写入（AT&T mov 源在前）。
退出置僵尸并立即调度；更晚的调度只回收当前执行栈以外的僵尸任务，释放用户页、用户页表、页目录和内核栈，槽位重新可用。
M7 起 BSS 位于 0x100000，链接断言 `__bss_end <= 0x200000`；引导栈与初始化段保持原位置。§1 的精确地址属于 M2 历史快照。

### M8 私有图形堆与真彩色后台（2026-10-02）

上段507页/BSS后台属于最初槽位底座。用户要求真正RGB后，原生后台改为
2025页（8294400B），VGA静态64000B不变；ARGB窗口页按cw×ch×4向上取整。
旧索引窗口继续一字节一像素，win_t的80B诊断布局保留，格式按稳定句柄扩展关联。

代码/BSS/普通栈/异常栈仍在原0x400000..0x7FFFFF，SCX头和旧上限未变化。
大图使用独立私有0x40000000..0x43FFFFFF图形堆（64MB），对应16张懒分配页表。
不能简单扩低端USER_TOP：8MB以上的内核画布/物理别名也需在调用者CR3中恒等可达。
高端堆避开PF最大256MB物理区和现有显存BAR，用户仍不能访问supervisor别名。

USERALLOC按4096B取整、逐页清零，只要求虚址连续，物理帧可碎片化。块首/块尾
记在仅内核能改的PTE软件位9/10。USERFREE只能从首地址扫描完整块，拒绝中间页、
重复释放、代码/栈地址；先验证再释放，不使用用户堆头判断长度。分配中途OOM
会归还全部已分配页和空页表；释放后刷新当前CR3，不留下过期TLB映射。
退出仍延后回收当前内核栈，并回收所有带US的私有页表；暂停任务保留堆。
用户缓冲验证/跨任务调试复制现在逐页检查两个私有区，拒绝间隙与未映射页。

### M7 暂停、异常栈与跨任务读取（2026-10-02）

任务 state=3 表示异常/调试暂停，调度器跳过但不释放地址空间。关闭异常卡片
才置僵尸。异常处理器独占一页 0x7DF000..0x7DFFFF，普通栈上限 128KB
（0x7E0000..0x7FFFFF），映像+BSS 上限 0x3D0000B，三者不会重叠。
SCX 文件中转上限 256KB。STATUS 在回收后保留退出码直到任务槽复用。
调试逐页解析目标私有 PTE，经 supervisor 物理恒等别名复制；不切 CR3，
不返回内核地址，先校验完整范围，失败不部分写入。模块地址合同另见 MODULE.md。

模块永久区为 0x01800000..0x018FFFFF，main 在用户分配前用 PF 位图预留；
所有页目录仍以 supervisor 恒等映射访问它。M7 大画布将当前 BSS 尾提高至
0x1EF8E0，仍低于 2MB 保留边界（含统一字体永久缓冲）。宿主 C 程序 BSS 不再物化到载荷，由符号表
生成 SCX bss_size；普通 C 栈采用 128KB，汇编程序保持原建议长度。

2026-10-02：字体永久缓冲增至 65536B、活动表最多 128 汉字，BSS 实测末端 0x1EF8E0；由链接断言继续保护 0x200000 堆起点。

2026-10-02：SCB2壁纸/图标占连续物理页，不进入低端BSS或应用4MB映像；32项按路径/偏移缓存，重载释放旧资源，失败候选释放。desktop_pages记录常驻资源，PF退出检查扣除此项主题变化，不能将永久缓存变化误报为应用泄漏。
