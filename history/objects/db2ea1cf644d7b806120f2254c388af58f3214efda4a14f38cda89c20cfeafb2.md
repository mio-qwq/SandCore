# SCCC：原生 C 编译与系统内自编译 v0.2

> 作者 mio。命令 `s3c`，公共头文件 **SCAPI.H**。18 组原生语言测试、四组失败诊断
> 和 G1→G2→G3 收敛均已通过；七个 M7 应用由 G2 生成并实际运行。

## 1. 编译链

`s3c 源文件 输出.scx`：读取 SandFS 文件、展开宏/包含文件、建立类型与语法树、
生成 32 位 x86 机器码、解决函数/全局地址、封装 SCX1MIO。整个过程在 ring3
运行，不调用宿主编译器。诊断保存到输出文件名追加 `.log`（路径过长则 HOME/S3C.LOG）。
符号与源码位置另存 `.map`，用于图形调试器关联函数。没有 libc/浮点依赖。

编译器源码分为 s3c.c 和几个内部 `.inc`，它们是同一编译单元的源片段；
公共应用接口只有 SCAPI.H。首次用 WSL GCC 构建启动版本；随后在系统内
从 SYS/SRC 源码编译第一代与第二代 SCCC，比较输出，再编译 M7 应用。

不把“基本 C”称为完整 ISO C：本版本不承诺浮点、64 位整数、可变长度数组、
标准库、结构体按值调用/返回、完整 GCC 扩展或优化器。超范围语法必须给出
文件/行号/原因并失败，不能静默换成其他语义。容量上限随实际分配布局核对后登记。

## 3. 测试与证据

每组语法先编译/运行一个有可核对返回码或文件输出的程序，再做错误用例。
宏测试覆盖嵌套、注释/字符串边界、参数展开、字符串化与拼接、条件分支及包含守卫。
自编译必须记录实际生成文件长度/摘要和运行结果，不能用宿主产物代替测试输出。
所有生成的应用经 Windows 无头 QEMU 双盘运行，图形验证保存截图。

## 4. 当前实测与容量

`build/m7-compiler/results.json` 记录 Windows 双盘 QEMU 实测：18 组 C/宏
语义写 PASS；启动版产生原生 G1，G1 产生 G2，G2 实际产生 G3，三份 SCX
逐字节相同；G2 编译测试源所得机器码相同，生成程序重新运行并写独立
HOME/C-RESULT2。`commands.json` 保存完整提交命令，每次 Enter 前另拍截图。

曾有一次自动输入过早、编译窗口尚未退出而吞掉命令开头。已改为等待
任务退出/窗口关闭/焦点归 Shell 后输入；旧图放 history，不是通过证据。
G0 指宿主启动版，G1/G2/G3 指真实原生生成次数，避免“第二代”口头混淆。
