# M9 双串口与宿主工具

> UART、SYSTEM管理帧、双向文件工具与真实Ring0调试源码已接线；
> 全部未构建/运行，不能宣称连通、最高权限隔离或调试验收通过。

## 1. 硬件与权限

这是双机调试模型：SandCore 是被调试机，另一台调试机从其外部物理串口接入。
QEMU 客体模拟被调试机，宿主连接工具模拟外部调试机和线缆；本机 named pipe
只是模拟线缆的宿主实现，不是 SandCore 内部设备文件，也不是网络登录后门。
真实机器仍只认外部物理 UART RX；QEMU 客体内同样不能自连这个模拟外部口。

首个工程实现使用 QEMU PC 的 16550A 两串口，115200、8N1：

| 通道 | 端口/IRQ | 最终用途 |
|---|---|---|
| COM1 / debug | 0x3F8 / IRQ4 | 独立 Ring0 调试，不依赖 GUI/Shell/任务调度 |
| COM2 / management | 0x2F8 / IRQ3 | 外部管理 Shell、SYSTEM 与双向传输 |

RX/TX 队列按通道独立、容量有界；IRQ 只收字节/发送积压，不在 IRQ 内调用文件
系统、创建进程或执行传入代码。没有输入时不忙轮询；紧急调试另用有界发送与直接
轮询入口。普通/root 三环没有 raw-UART syscall、设备节点或注入队列入口。
UART 初始化始终关闭硬件回环，配置只在可信内核控制下修改。

内核凭据区分普通、启动服务和外部串口SYSTEM管理，最高写入权限另查realm/会话。
没有普通SYSTEM登录，也不给客体端口IO或UART控制；Ring0授权代码本来就最高权限。

## 2. 本机连接

自写 tools/scserial.py，Windows QEMU 使用两个独立本机 named pipe；
Windows 是单条双向 pipe，不使用 Linux 的 .in/.out 双 FIFO 约定。
QMP 验收控制使用父子进程间匿名stdin/stdout pipe，禁用 TCP monitor 和客体网络。
宿主工具启动时先暂停 VM，连接并限制通道 ACL，再允许客体开始执行。
管道ACL显式拒绝NETWORK身份，仅宿主当前账户与SYSTEM；连接回读ACL并核对
本次QEMU服务端PID。每次外部工具使用新的强随机fw_cfg种子，供内核生成
启动随机令牌；种子不是串口登录请求，也不向客体三环开放。
通道名使用随机会话名，启动日志记录原始命令、QEMU/镜像摘要和实际 PID。

工具源码已接:put/:get文件、管理Shell、:debug/:management通道切换、:hmp与
实际输出/原始日志。截图由客体capture生成BMP后:get取回，不用宿主截屏冒充。
当前均未运行；代码存在不能代替实际收发或客体截图证据。

宿主`:raw`进入管理终端逐键输入，Ctrl-]回到宿主菜单，不向客体发送这个
退出键。Windows控制台保存/恢复原模式，直接收键事件并转义方向/Home/End/
Delete/Page及功能键，UTF-16代理对合为UTF-8，粘贴/重复键按512B帧批发送。
raw模式下nano的Ctrl-O/Ctrl-X等由客体处理；`:put/:get/:debug`在返回菜单后使用。
串口TTY暂定80×24，窗口TTY按实际网格；未实现外部窗口尺寸协商。
输入端仍来自同一外部COM2帧，不给客体增加UART或自连权限。

三环CLI命令`scdbg`创建自己的调试目标并使用DBGSPAWN2/DEBUG。它能检查
本目标寄存器/断点/内存/栈，不能调试内核或取得SYSTEM；零环现场调试仍由
外部COM1的`:debug`提供。三个CLI和raw输入均为未运行源码状态。

Windows pipe 后端当前在初始化时等待客户端，必须保持两串口连接，不能只连
COM1 就期待 VM 已启动。物理 COM 后续由同一工具的串口适配层接入；本轮验收
只以 QEMU 为目标。

## 3. 管理帧与调试源码合同

管理流中的终端文本、文件数据与控制帧必须可区分；双向文件传输提供序号、
长度上限、校验、ACK/重传、取消和完成确认；控制帧不会经过普通 Shell 文本解析。
CRC 只处理传输损坏，不是 SYSTEM 认证。随机令牌、可信来源和会话权限由内核
身份层处理。文件接收的最终发布必须在完整长度/校验验证后进行，并重新核对权限。
失败保持旧文件和可说明的临时资源状态。

Ring0 调试器控制现场、软件断点与单步，暂停期间可读写现场和内存；继续运行
前恢复断点/标志/中断现场。不可读内存与错误输入不能让调试器自身再次异常。
调试权限只能从外部 debug 串口取得，不开放到网络或普通/root 程序。

COM2帧为0x7E包围，0x7D转义下一字节xor0x20。解码正文为SC9\0、
u16 type/u16 flags(0)/u32 sequence/u32 length、至多512B正文和CRC32。
请求序号非0，同序号+同内容重试返回缓存ACK，不重复提交。ACK type|0x8000，
正文首i32结果。串口终端输出type0x100/seq0，二进制与文本不混解析。

| type | 请求 | 回应补充 |
|---|---|---|
| 1 HELLO | u32 version=1 | 1/max512，创建外部会话及SYSTEM SH |
| 2 INPUT | 终端字节 | 接收长度/错误 |
| 3 PUT_BEGIN | u32长度+SHA256[32]+NUL路径 | 新流式事务 |
| 4 PUT_CHUNK | u32 offset+至多508B | 顺序长度检查 |
| 5 PUT_END | 空 | 整长度+SHA核对后一次提交 |
| 6 CANCEL | 空 | 放弃传输 |
| 7 GET_BEGIN | NUL路径 | 大小/对象代数 |
| 8 GET_CHUNK | u32 offset | offset+至多500B |
| 9 GET_END | 空 | 完整SHA256 |
| 10 PING | 空 | 延长外部连接租约 |
| 11 BYE | 空 | 撤会话/停止管理链任务 |

管理租约30秒、未完成RX帧2秒；断开先撤授权、取消暂存并停止带此会话的后代。
上传CORE/AUTH始终拒绝；MOD上传仅这条真实外部会话调用内核私有事务。
CRC是误码检查，SHA验证文件完整；可信UART入口与内核凭据决定SYSTEM权限。

COM1使用ASCII行命令hello/help/halt/regs/mem/write/break/clear/step/cont，
数值均十六进制。mem最多256B，write为连续hex字节；断点最多16个，实际
INT3/TF步进，不伪造现场。halt由硬件IRQ现场进入暂停，暂停时直接轮询
UART且不运行文件系统/调度/GUI；在禁止IRQ的内核死循环里不能承诺无NMI暂停。
已预置断点可以在其实际指令位置进入。CPL0错误在已armed的调试会话中停住；
未armed仍沿原panic路径。内存范围检查只针对已映射真实RAM，排除三环私有区。
