> 作者 mio。2026-10-02 用户要求先比较多套可交互原型，再指定最终设计语言。
> 当前状态：用户已选择极光，配色改为漂亮的白色；增加 Classic 经典主题。

## 1. 为什么在这里增加一个选型步骤

用户明确反馈：现有图标不好看，不要把所有程序都放在同一种纯方形底板里。
这次需要一起确定图标轮廓、窗口形状、布局密度、色彩与层次，再用于全部组件。
因此不能只给现有桌面换一种颜色，也不能先把某一套风格写进内核，再要求用户接受。

已经实现的高分辨率、窗口和三环工具功能基础继续保留；最终视觉规则在用户选择后
落到实际源码。浏览器原型用于比较设计，系统功能是否通过仍以 Windows 双盘 QEMU
的行为与截图为准。两类证据独立记录，避免把原型按钮的提示当成真正的系统编译或保存。

## 3. 候选原型包含什么

同一套原型可切换 Files、Lens、Canvas、Studio、Debug、Settings；每套都有桌面、
任务栏、开始菜单、窗口按钮、文件浏览、显示设置、工具栏与右键菜单。
开始菜单与桌面图标能切换工具；窗口可以隐藏并从任务栏恢复，最大化按钮切换布局；
Canvas 支持鼠标落笔；其余保存、编译、调试提示是局部演示状态，不会修改 SandFS。

候选页使用的图形轮廓属于浏览器预览资源。正式系统图标需要按用户选定风格重新绘制
为带透明度的高分辨率真彩色 SCB；原调色板/SCF 兼容路径保留，不引入浏览器运行时或外部图标库。

文字方面，模拟系统的 ASCII 控件直接使用当前生成表 `build/font8_data.h` 中的
`sc_latin16`：95 个字形，每字 16 行、宽 8px。没有另外生成一套相似字体，也没有编辑
`kernel/font16.txt`。候选页的中文风格名称是预览的辅助标签；正式系统的汉字仍只能
取统一凤凰字库，需要增加文案时按 `tools/import_font.py` 流程补字。

## 4. 选定后需要一起重写的组件

| 范围 | 需要定下并统一的规则 |
|---|---|
| 开机与桌面 | 构图、壁纸层次、图标轮廓、快捷方式标识、名称位置、选中/悬停状态 |
| 窗口与任务栏 | 活动/非活动标题栏、关闭/最小化/最大化、缩放边缘、恢复、菜单和光标 |
| 共享控件 | 主/次/危险按钮、禁用状态、导航、列表、滚动/分页、输入框、提示和确认/取消 |
| 原生工具 | Files、Studio、Debug、Settings、Lens、Canvas、Monitor 的布局和鼠标操作 |
| 原有工具与游戏界面 | Shell、Notes、Palette、Calculator、Mines，以及游戏菜单/HUD 的公共元素 |
| 异常与失败路径 | 三环异常卡片、非法配置、文件错误、编译失败、显示回退的提示与可恢复操作 |

选定后先写正式组件规范，再同步 `docs/GFX.md` 的槽位和 `kernel/palette.h`，然后
重写内核桌面/窗口装饰与用户态共享绘图片段。保留旧 SCF 图标、旧窗口画布和 VGA 回退，
不能让统一视觉升级破坏已有程序的加载、输入或退出回收。

网页的 CSS 阴影/光感不会原样复制到内核。实际系统要用整数绘图、已登记颜色槽位和
有边界的重绘成本表达同一套层次；1080p 的清晰度、缩放与帧率需要另外上机验证。

## 6. 用户最终选择

用户已明确选择 **Aurora / 白色极光**。主窗口使用白色与浅蓝白层次，深色正文、
柔和圆角、薄边缘、适度投影；图标是彩色物件轮廓，禁止统一纯方形底板。
旧深色极光候选只保留为选择过程，不再作为最终配色。版本主题为 **Welcome to true color**。

同时提供 **Classic / 经典**：致敬 Windows 2000 的青绿桌面、灰色立体控件和紧凑
信息排列，结合 SandCore 原来的青色/暖沙强调；保留原设备与 API。
用户可通过主题配置修改命名色彩、组件参数与系统快捷方式图标。系统预装快捷方式
可以跟随主题；SCX 内置图标保持应用身份，主题切换不覆盖它。用户显式指定快捷方式
图标时使用该指定资源。所有主题仍使用统一凤凰字体，不另绘相似字形。

壁纸提供摄影风格与独立 Logo 构图。用户否定了最初过于光滑的白沙湖泊及水面 Logo。
2026-10-02 重做海岸摄影、白色极光 Logo、青绿经典 Logo 三款；资源、实际尺寸、
完整生成提示在 `assets/wallpapers/generation.json`。这批为 1672×941 原始生成图，
不宣称原生 4K。系统最终安装和截图效果仍需完整真彩色链路验证。
