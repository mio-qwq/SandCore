# SandCore 启动协议（Boot Protocol）v0.4

> 本文定义"磁盘上是什么"和"引导器交给内核时 CPU/内存处于什么状态"。
> 这两件事是**引导器、内核、打包器三方共同的合同**，任何一方改动必须同步修订本文。

## 0. 铁律：QEMU 必须以软盘方式挂载镜像

```
-drive format=raw,if=floppy,file=build/sandcore.img
```

**`if=floppy` 绝不可省略！**（M2 调试实录）缺省时 QEMU 把镜像挂成 IDE 硬盘，
SeaBIOS 走 LBA 辅助映射：我们的 CHS 几何(18扇区/2面)在柱面 0 磁头 0 上恰好与
LBA 重合，M0/M1 一直"碰巧正常"；内核一涨到 24 扇区、读到**磁头 1**，CHS(0,1,1)
被翻译成完全错误的 LBA，读回来的是全零填充区——内核后段(.rodata 尾部)变成
零，IDT 门属性常量(0x8E)读成 0，第一个时钟中断就 GP→三重故障→重启循环。

## 1. 上电到画面的完整流程

```
电源上电
  │
  ▼
BIOS POST 自检
  │  把启动盘 LBA 0 (512B) 复制到内存 0x7C00, 校验末尾魔数 0xAA55
  ▼
boot/boot.asm  [16 位实模式]
  │  1. 归零段寄存器, 在 0x7C00 下方搭栈
  │  2. int 15h AX=E820 采集内存图 → 0x7E00 (实模式最后的机会!)
  │  3. int 13h 一次一扇把内核读进 0x10000
  │  4. int 10h 切 VGA 13h 图形模式 (320x200x256)
  │  5. 端口 0x92 打开 A20 地址线
  │  6. 装载自建 GDT, 置 CR0.PE, 远跳刷新流水线
  ▼
kernel/entry.asm  [32 位保护模式, CPL0]
  │  清零 .bss 段
  ▼
kernel/main.c kmain()
  │  等垂直回扫 → 配调色板 → 画沙漠落日 → hlt 死循环
  ▼
屏幕出现 SANDCORE 画面
```

## 2. 磁盘镜像布局（1.44MB 软盘）

镜像文件 `build/sandcore.img`，1474560 字节，CHS 几何 **80 柱面 × 2 磁头 × 18 扇区 × 512 字节**。
SandCore **不使用任何文件系统管理引导区**，布局是固定的：

| LBA | 扇区数 | 内容 | 定义者 |
|---:|---:|---|---|
| 0 | 1 | 引导器（末两字节必须是 `55 AA`） | `boot/boot.asm` |
| 1 .. 256 | ≤256 | 内核纯二进制镜像（无头，第一字节即可执行代码） | `tools/mkimg.py` |
| 257 .. 2879 | — | 未用；SandFS 位于独立 IDE 数据盘，见 FS.md | 预留 |

**三处必须保持同步的常量**（改一个 → 三个都改）：

| 常量 | 位置 | 当前值 |
|---|---|---:|
| `KERNEL_LBA` | `boot/boot.asm` | 1 |
| `KERNEL_SECTS` | `boot/boot.asm` | 256 |
| `KERNEL_SECTS` | `tools/mkimg.py` | 256 |

mkimg.py 会主动校验内核大小不超过 256×512=128KB，超限直接报错拒绝打包。

### LBA → CHS 换算（int 13h 只认 CHS）

```
扇区号(1基) = LBA mod 18 + 1
磁头       = (LBA / 18) mod 2
柱面       = LBA / 36
```

BIOS 读盘的坑（M2 调试实录）：成块多扇区读在 QEMU 虚拟 FDC + BIOS 组合下
不可靠——M1 的 17 扇区内核（单道）一直正常，M2 涨到 24 扇区后从第二道起
读回的全是 0。所以**一次只读一扇**，慢几毫秒，百发百中。

## 3. 内存地图（M0 阶段）

```
0x00000 ┌────────────────────────┐
        │ 实模式中断向量表 IVT     │ (引导期用, 进保护模式后作废)
0x00400 ─┤ BIOS 数据区             │
        │                        │
0x07C00 │ ★ 引导器 (512B)         │
0x07E00 │ ★ E820 内存图            │ 条数(4B) + ≤32条×24B (见 §4.5)
        │   (引导器数据/GDT 尾部)  │
        │                        │
0x10000 │ ★ 内核镜像基址           │ 纯二进制, entry.asm 的 _start 在此
        │   .text / .rodata/.data │
        │   (.bss 只占地址不占盘)  │
        │                        │
        │         (空闲)          │
        │   内核栈: 0x90000 向下生长│
0x9FC00 ─┤ EBDA (BIOS 保留区)      │
0xA0000 │ ★ VGA 图形显存 (13h)     │ 320x200=64000B, 1 字节 1 像素
0xB8000 │   VGA 文本显存 (引导期用) │
0xC0000 ─┤ 显卡 BIOS / 硬件保留    │
        │        ...             │
0x100000└────────────────────────┘ 1MB 边界 (A20 未开时不可达)
```

## 4. 引导器 → 内核交接契约

内核第一条指令执行时，系统**保证**处于以下状态：

| 项目 | 状态 |
|---|---|
| CPU 模式 | 32 位保护模式，特权级 CPL0 |
| 段寄存器 | CS/DS/ES/SS/FS/GS 全部为平坦段：基址 0，上限 4GB |
| A20 | 已打开（4GB 可寻址） |
| 分页 | **未开启**，线性地址 = 物理地址 |
| 中断 | **已关**（IF=0），且没有任何 IDT——内核开中断前必须自建 IDT |
| 栈 | ESP ≈ 0x90000，向下生长 |
| 显卡 | VGA 13h 模式已设好，调色板为 BIOS 默认（内核需自配） |
| 磁盘 | 已读完，不再需要 BIOS |
| BIOS 服务 | **全部失效**，内核不得调用 int 10h/13h/15h 等 |
| 启动信息 | E820 内存图在 0x7E00（见 §4.5）；启动盘号无保留（不再读盘） |

## 5. 引导器内部约定（改 boot.asm 前读）

- 引导器整扇区只有 512 字节，GDT（24 字节）+ 描述符（6 字节）直接嵌在扇区尾部数据区，代码+数据总和不得超过 510 字节，`times 510-($-$$)` 负数时 NASM 会直接报错——这是天然的体积红线。
- 读盘重试策略：失败后先 `int 13h AH=00` 复位控制器再重读，每扇最多重试 4 次，全失败则打印 `disk error` 停机。

### §4.5 E820 内存图契约（v0.3 新增）

| 项 | 值 |
|---|---|
| 条数 | `*(u32*)0x7E00` |
| 条目 | 0x7E04 起，每条 24 字节：`base_lo/base_hi/len_lo/len_hi/type_lo/type_hi`（各 u32，小端） |
| 容量上限 | 32 条（超出放弃采集） |
| 类型值 | 1=可用 2=保留 3=ACPI可回收 4=NVS 5=坏 |
| 采集方式 | int 15h AX=E820，EDX='SMAP'，ECX=20，EBX 游标循环 |
| 规格化 | BIOS 的 20 字节条目本就是 24 字节布局的前缀，只需清零 `entry+20` 的高 4 字节——**切勿重排数据**（会把类型搬进下一条的地盘） |

内核侧解析：`kernel/memory.c` 的 `memory_init()`；展示：shell `mem` 命令。
- GDT 三条：`0x00` 空描述符（CPU 规定）、`0x08` 代码段（基址 0/上限 4G/可执行可读/4K 粒度/32 位）、`0x10` 数据段（同上可读写）。位域详解见 boot.asm 注释。

### M7 容量修订（2026-10-02）

引导器仍是 512B，每读一扇 ES 前移 32 段、BX 恒为 0；跨 64KB 不回绕。
初始化段限制 0x10000..0x2FFFF，BSS 无盘上内容，移至 0x100000 起，
链接断言末端不超过 0x200000；引导栈 0x90000 不再与画布/中转缓冲争空间。
256 扇区额度由 boot.asm、mkimg.py、本规范三方同步。后续 SKM 组件从 IDE
数据盘由已启动内核加载，约定目录与格式见 MODULE.md。
