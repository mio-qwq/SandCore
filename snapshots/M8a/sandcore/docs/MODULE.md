# SKM1MIO：零环模块与核心保护 v0.1

> 作者 mio。开机加载/重定位/回调和非法格式拒绝已通过 Windows QEMU。
> 文件名与约定目录完全大写；编译器应用头文件为 SCAPI.H。

## 1. 目录与职责

`/SYS/CORE/CORE.SKM` 是随系统发布的核心模块；`/SYS/MOD/*.SKM` 是用户编写的
零环扩展。内核启动文件系统后先按目录顺序加载 CORE，再加载 MOD。普通三环 SCX
不进入这条加载链。SKM 有内核权限，其异常进入内核 panic；三环异常隔离规则仍见 INTR.md。

CORE 首次迁入桌面壁纸绘制，用来验证模块确实参与系统运行。引导期画面仍有内核
兜底，缺失/格式错误/初始化失败不安装该模块的回调，桌面继续用兜底绘制。
加载完成后模块映像与 BSS 保持有效到关机，不热卸载。

## 2. 文件格式

| 偏移 | 大小 | 内容 |
|---|---|---|
| 0 | 8 | `SKM1MIO\0` |
| 8 | 4 | 初始化入口 RVA |
| 12 | 4 | 装载字节数 |
| 16 | 4 | BSS 字节数 |
| 20 | 4 | 绝对地址重定位个数 |
| 24 | 4 | 模块服务 ABI，目前 1 |
| 28 | 4 | `MIO\0` |
| 32 | load_size | x86 平映像，链接基址为 0 |
| 随后 | reloc_count×4 | 每项为载荷内待修补双字的偏移 |

加载时分配共享 supervisor 区 0x01800000..0x018FFFFF 中的整页区域，复制载荷、
清 BSS，并对每个绝对重定位双字加实际装载基址。PC 相对内部引用不需修补。
单模块载荷/BSS 各不超过 128KB，总量不超过 256KB；重定位最多 8192 项。
加载器先验证头、完整长度、每个偏移及容量，再执行入口，失败不执行部分映像。
重定位表须严格递增且相邻项至少相距四字节，禁止双字重叠；被修补值须落在
该模块载荷/BSS 内。mkskm.py 与加载器同批执行此合同，防止重复加基址。

## 3. 模块服务 ABI 与保护

初始化函数采用 32 位 cdecl：`int module_init(const module_api_t *api)`。
module.h 定义版本、尺寸以及绘图/壁纸模式/安装场景回调服务；模块经服务表
调用内核，禁止宿主链接未定义符号。新增服务在表末尾追加并核对 version/size。
宿主工具 mkskm.py 从 ELF 的 R_386_32 提取重定位，其他不支持的类型直接拒绝。

内核系统调用入口统一禁止三环写入、删除、重命名 `/SYS/CORE` 本身及后代，
也禁止通过移动其祖先目录绕过保护。先处理根斜杠、重复斜杠、`.`/`..`，再
按 ASCII 大小写折叠比较；它不依赖磁盘权限位或编辑器按钮。`SYS/MOD` 可编辑，
下一次开机才加载新增内容。可信零环代码拥有内核权限，不假装受三环保护规则限制。

## 4. 修订记录

36B，旧前缀不挪位。旧模块继续使用旧服务；新版CORE先检查size>=36才
调用扩展，旧内核遇到新版CORE初始化失败并用兜底，不读不存在的表尾。
