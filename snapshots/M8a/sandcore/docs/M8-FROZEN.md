# M8 暂时结束与封存记录

作者 **mio**，封存日期 **2026-10-04**。本页是封存后的当前入口，覆盖其它文档较早的“继续实施”“队列正在运行”“必须自主推进到完整交付”等运行状态。旧记录保留说明当时做了什么，不再代表当前授权。

## 1. 用户决定与版本口径

用户明确要求：“现在这些东西保留，M8 暂时封存”“现在我们宣布 M8 暂时结束”。用户认可 **M8a 的组件成果和真彩色已经完成**，同时指出游戏的 CPU 负担和当前设计不合理。这是用户批准的阶段收束，不是代理自行放弃，也不是将未达标条目改成通过。

用户随后进一步明确：**目前的成果已经够用，而且很优秀，只是部分未完成；暂时跳过 M8。** 当前版本主体成果得到用户认可，保留为可用基础。封存针对继续追赶剩余目标的工作，不应将 M8 描述成整版失败，也不回退已完成的真彩色和用户组件。

**最新发布决定：当前成果命名为 M8a，现在发布。** 见 [M8A-RELEASE.md](M8A-RELEASE.md)。M8a发布和完整M8余项封存同时成立；未达成预期随发布说明公开。本次收束/更名/跳过均由用户明确批准，以后未经许可不得擅自重复。

因此从本次封存起：

1. 停止 M8 新功能、游戏优化、构建、客体编译、QEMU 测试和影片渲染；不自动开启下一里程碑。
2. 保留全部已写源码、资源、游戏内容、库、编译器改进、历史镜像、测试截图、成功及失败证据、Blender 工程和数学渲染工程。
3. 将真彩色和组件成果记录为用户认可的阶段成果；“M8a”在此采用用户本次称呼，不另造一个已经完成全套验收的发布包。
4. 完整 M8 原先约定的现代游戏画质/流畅度、全系统最终矩阵、成片/播放器、统一原生发布与最终验收包保持未完成，转入封存待办，不再持续执行。
5. 再次修改产品、渲染或运行测试必须有用户新的明确继续指令；仅阅读本记录不能恢复旧的自动推进授权。
