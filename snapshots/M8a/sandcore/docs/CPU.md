# M8 CPU采样分析

> 作者mio。此合同增加0x79，不改变0x26 MONITOR的192B输出或168B任务表。

## 1. 测量范围

单核客体在100Hz PIT的IRQ0、轮转之前记录被中断上下文。任务0仅在
`sti; hlt`之前标为空闲，恢复主循环后立即清除；其它任务执行用户
代码算用户样本，CS属于零环则算内核样本。任务0合成期间内核样本
另外计入图形子集，内核比例已经含图形，不能再相加。

100个样本约为一秒；短于一tick的调用不能逐个测量，长时间IF=0的
系统调用、磁盘PIO可能延迟/合并PIT，因而这是可观察执行状态采样，
不是精确周期计费。结果代表客体，不能等同宿主QEMU进程CPU占用或
物理机器性能。任务0进入HLT后轮转唤醒仍视为空闲直到主循环恢复。

大帧FRAME/FRAME32的可信内核复制已改为开IRQ且暂缓任务切换，
这段现在有机会计入kernel及该调用者的运行样本；graphics字段
仍只包括任务0合成，不改变已发布布局/含义。短于10ms的复制
可能完全没采中；其它IF=0的磁盘IO等精度边界仍然存在。内部
render_copy_ticks仅验收诊断，不新增CPUINFO字段或用户写入口。

## 2. 固定输出64个u32

0x79：EBX=完整256B用户缓冲；成功0，映射非法-1且整块不写。

| 偏移字 | 含义 |
|---|---|
| 0/1/2 | 协议1、100Hz、当前tick |
| 3/4/5/6 | 总样本、空闲样本、内核样本、用户样本 |
| 7/8/9 | 图形样本(内核子集)、8个任务槽、方法1=PIT状态采样 |
| 10..15 | 保留0 |
| 16+i*6 | pid |
| +1/+2 | state沿用旧表；槽代数，每次复用递增，任务0固定1 |
| +3/+4/+5 | 运行样本(含本人内核样本)、切入次数、保留0 |

计数无符号回绕。使用两次快照的`delta分类/delta总样本`求占比；
没有样本应显示采样中，不伪造0%。每任务只有代数一致可求差；复用
取新计数。空闲样本不加入任务0运行样本，因此每任务总和对应忙碌。
退出前样本保留直到复用，全局分类独立累加，任务关闭不造成CPU倒退。

## 3. 用户界面与验证

Monitor每秒取差分，显示CPU历史、内存历史、分类与任务占用；Freeze
只冻结视图，Resume重置差分基点，不能把冻结期间计数塞入一秒。
cpu命令创建真实采样窗口，ps读取任务和CPU旁表。原MONITOR仍可用于
旧程序。需实测空闲、三环负载、图形负载、任务复用和非法缓冲。
