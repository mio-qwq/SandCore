### 实现与工程变更

1. **SandAsm**：固定基址 0x400000、64 标签、两遍固定长度编码、36B SCX1MIO 头、行号错误；超长名字错误路径仍终止 NUL，末尾入口写盘前拒绝。
2. **Files/Notes**：目录列表与完整路径分别保存；文本关联经 EXEC 参数打开 Notes；4095B ASCII 正文、F2 显式保存、F3 重载、尾部七视觉行，保存字节不受显示滚动影响。
3. **Calculator/Mines**：i32 输入/i64 加减乘检查、除零和 INT_MIN/-1 先拒绝；8×6/8 雷、首格安全、最多 48 项的揭格队列、旗标/鼠标/方向键、40 安全格胜利与踩雷失败。
4. **Palette/桌面**：仅用 palette.h 已分配槽位，图标为独立 SCF 资源；sys/wall.cfg 保存一个 0/1/2 模式字节，内核先保存再切换，启动重读。
5. **系统基础**：SandFS v3 八扇区目录/96 项、旧单扇区盘兼容、末扇区中转、路径与盘界校验；ATA 检查 BSY/DRQ/ERR/DF、超时及 flush 错误；目录保存失败传回用户程序。
6. **调度与输入**：普通系统调用原路返回、EXIT 立即调度，PIT 100Hz 仍抢占，消除每个绘字调用等一拍造成的 GUI 迟滞；稳定窗口句柄与独占画布仍维持 owner 路由。
7. **构建**：WSL ELF 主力、Windows QEMU；新增用户态 C 入口/cdecl 桥/平映像链接，头依赖自动追踪，禁 libc/浮点/MMX/SSE，构建器与链接器强制容量/栈边界。
8. **中文注释**：核心分页/任务/画布/文件 IO 与应用解析/编辑/算法/鼠标逐层坐标都解释设计原因、容量、所有权、失败路径及不变量；公共接口先在头文件说明契约。
9. **文档**：HANDOFF/README/ROADMAP/TESTING 与 BOOT/BUILD/SYSCALL/FS/INTR/MEM/WM/GFX/SHELL 同步；新增 ASM/APPS/本验收页，每份对应文档末尾保留修订记录。

## 2. 怎样验证

全部在 Windows 的 sandcore/ 目录执行：

```text
build.bat
python tools/verify_m6.py all
python tools/verify_apps.py
python tools/audit_m6.py
python tools/package_m6.py
```

`build.bat` 调用 WSL make，QEMU 使用 `C:\Program Files\qemu\qemu-system-i386.exe`。
两套上机脚本各自复制数据盘，顺序占用 4444/4445 监视器端口；结束只退出自己的 QEMU。
输入走 HMP sendkey 与 QMP 分沿鼠标，截图走 HMP screendump，行为断言走 pmemsave 或读取测试盘的实际目录/正文。

核心挂盘命令（各次完整参数已保存 qemu-command.json）：

```text
-drive format=raw,if=floppy,file=build/sandcore.img
-drive format=raw,if=ide,file=<本次复制的 sanddata-test.img>
-display none
-monitor tcp:127.0.0.1:4444,server,nowait
-qmp tcp:127.0.0.1:4445,server,nowait
```

M6a 断言字体实际激活 27 字、页表/CR0、窗口 owner、稳定句柄、画布摘要、10 轮回收物理页数不变、红叉与真实 ring3 除零。
M6 应用断言运行原生生成程序、三类汇编错误不输出、Notes 精确写入/重读/F3、Files 导航/打开、整数结果与三类异常输入、扫雷首格/旗标/鼠标/方向/胜负、壁纸写盘与 system_reset 后恢复。
测试为胜负读取雷区后驱动真实键盘，不修改游戏状态或雷阵；重启验证重新走开机按键和 wm_init，不能仅凭切换瞬间的画面判断持久化。

### 最终静态核对

- `audit_m6.py` 全部通过：Python 语法、ASCII 批处理、引导 55AA/双盘尺寸/载荷、SandFS 目录与 build/fs 逐文件一致、SCX/SCF/.lnk、用户字体摘要、BSS 边界。
- 内核及六个用户 C ELF 的 `nm -u` 为空，objdump 代码段未发现 x87/MMX/SSE 指令；没有额外运行库符号。
- 内核原始 32024B，盘内补齐 32256B = **63 扇区**，64 扇区合同未改；BSS 末端 `0x8b100` ≤ `0x8c000`。仅注释/头说明修订后的内核重编字节一致。
- 发布盘预装 **20 个文件**；测试盘另包含系统内生成的 demo.scx、编辑文本与壁纸配置。SHA256 与核对结果在 `build/m6-integrity.json`。

## 4. 验收包与当前边界

`build/SandCore-M6-2026-10-02.zip` 收录当前完整源码/文档/资源（含根目录源字体 ZIP）、可运行双盘、符号、两份实际测试盘、35 张截图、断言与命令记录、接手源码基线。
包内 manifest.json 记录每个文件的长度/SHA256，压缩后已重读校验每项；包旁 `.sha256` 可核对交付文件本身。
解压后在 sandcore/ 执行 run.bat 看窗口，或按上面的命令重建和重测；测试命令的路径按解压位置重新计算。

以下边界已明确记录，不能把原生汇编起步混写为完整自举：

- SandAsm 仅支持 ASM.md 列出的 NASM 子集，没有宏/完整内存寻址/完整 NASM；汇编器自身仍由宿主 C 编译。
- Notes 当前仅 ASCII 末尾追加/退格，不是任意位置或中文输入编辑器；Esc/红叉舍弃未保存修改。
- Files 使用路径前缀伪目录；壁纸是三种槽位预设，没有位图导入；SCX 内嵌图标与统一事件队列仍属可选后续接口。
- SandFS 不含日志/删除回收/事务；运行期文件保存到数据盘，资源变化触发 mkfs 会重建目录，保留个人文件时先备份整盘。
- 用户界面验收尚未收到确认；本页历史下一站为 M7（s3c/SCAPI.H/进一步下沉）。当前 M7 已自动化通过，联合操作见 TESTING.md。
