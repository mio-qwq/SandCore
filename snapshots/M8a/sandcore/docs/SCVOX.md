# SCVOX：调用者拥有的整数体素空间查询库 v1

作者mio，2026-10-04。`user/SCVOX.H`先声明接口，`SCVOX.inc`实现；
这是普通三环源库，SCAPI.H、内核调用号与既有用户缓冲布局没有变化。
scvox-01/02中旧M7和当前G2真正编译/运行，完整查询与工作区参考
通过；两轮实验性World接入的六图一致性也通过。成本对照发现
当前8格块索引在这类场景中反而增加开销，build-23已撤回默认
World接入，库与证据保留供其它应用独立使用/后续算法研究。
完整游戏性能仍未达标；库存在、查询正确和索引很小都不能代替
游戏可玩或60FPS验收。

## 数据与生命周期

应用提供`ScvGrid`、u8体素数组和u16占用计数数组。无隐藏分配、文件
读取、窗口或内核状态；独立应用/视图可用独立上下文。库不认识草、
玻璃或水：0为空，其余1..255都是可查询的非空材料。碰撞、透射与
光照由调用者解释，空间索引不能为了提速把水/玻璃当作空气。

格号为`(y*depth+z)*width+x`，宽/高/深各1..128。每格256个Q8位置
单位。调用者保证数组至少宽×高×深字节；库不越过合法格号读取。
占用块边长8，工作区至少`ceil(w/8)*ceil(h/8)*ceil(d/8)`个u16，
最大4096项/8192B。每项实际计数0..512，因此删除一个块内最后的
实体后，可精确恢复空块，不保留“曾经有物体”的陈旧布尔标志。

| 入口 | 合同 |
|---|---|
| `scv_bind(g,cells,w,h,d,chunks,capacity)` | 验证尺寸/工作区后绑定，成功0、错误-1；错误保持原上下文；不清空体素、不扫描世界，索引先无效 |
| `scv_rebuild(g)` | 先无效，清占用计数、扫描真实体素，全部完成才发布valid；工作区尾部不写；错误-1 |
| `scv_invalidate(g)` | 直接批量改数组前使用；NULL可安全忽略；原指针/尺寸保留，之后查询回退逐格 |
| `scv_write(g,index,kind)` | 索引和u8材料范围先检查；有效索引只在空/非空状态变化时加减占用；非零互换不改计数；无效时也允许合法编辑但不发布有效 |
| `scv_query(g,origin,direction,distance,skip,hit)` | 同步整数射线查询，返回0或-1；未建/已失效索引走原逐格路径；无分配、无最终颜色缓存 |

元数据由库维护，调用者不任意改上下文字段。数组、尺寸或工作区
换了须重新bind；工作区释放/复用前使旧上下文不可再查询。所有
直接写cells的高级用法先invalidate，完成后rebuild；库无法自动
侦测用户任意内存写入，不能暗称“直接写也永远自动正确”。

## 射线与完整命中合同

起点Q8，方向各分量绝对值≤8192，保留整数幅值；零向量未命中。
距离1..16000 Q8。内部长度为精确整数下取整平方根，参数t为Q16，
delta仍按`floor(256*65536/abs(direction))`累计。合法范围保证
平方和与块边界事件的i32算术有界；零轴用0x3FFFFFFF哨兵且不会
实际跨越，不能把哨兵乘8而溢出。最多检查192个单元，与原World一致。

`ScvHit`含found/index/previous/kind/distance，以及Q8位置p和外法线n。
未命中只定义found=0和index=previous=-1；其它字段保留原内容。
起点所在格在t≤1时不作为命中。skip只忽略指定实体，不把它变成
空气；previous仅记录最后真正为空的单元，建造不能因此覆盖玻璃/水。

多个轴在同一t相遇时，依X、Y、Z先后跨越，只在第一个实际命中格
停止。块跳跃合并同一批等差事件，保留这个顺序和命中前的最后空格；
不是一次把三轴跨到对角格，也不是重新用近似浮点/AABB求块交点。
非8整倍世界的边块同时裁到真实尺寸。距离和192步上限不放宽。

## World实验接线与撤回

64×24×64世界只需8×3×8项计数，共384B；旧24×12×24使用同一
任务私有工作区重新绑定，旧存档格式/LEGACY原SCX不改变。主、阴影、
反射、透射和交互射线共用该库。批量生成、成功旧/新读档先失效；
world_put、采集、建造用单格write；第一条新世界射线按需重建。
相机、昼夜和材质外观变化不改变占用，不因此扫描整个世界。
以上是保留在before-scvox-02及实验产物中的接线设计。实际两轮
成本对照未得到净收益，当前默认World已经恢复原逐格DDA和原编辑
路径；SCVOX.H/inc仍安装到源库目录，未减少SCAPI.H的任何API/ABI。

## 验证格式与范围

`tools/verify_scvox.py`准备五种尺寸：64×24×64、24×12×24、17×9×31、
1×1×1、128³。每种1024条射线，独立Python最小堆参考合并三轴事件；
覆盖同距、极小/零方向、边界/世界外、skip、短/远距，以及空→玻璃→
水→空气、批量失效期间查询及重新建索引。客体分别用线性/加速
上下文运行每条，回传全部12个u32（返回值+11个命中字段）。
每种五次回传整个4098项u16工作区，包含首/末与未使用区护栏；
坏容量绑定必须保留全部48B元数据，错误单格编辑不得修改状态。
旧M7编译器和当前收敛G2真正生成并执行相同源码，关闭后严格页回收。

输入SVXI1MIO：32B头（版本/世界数/射线数及保留），每世界24B描述
（宽/高/深/体素数/射线数/编辑格号），随后体素、补齐4B、每条8i32
（起点3、方向3、距离、skip）。输出SVXQ1MIO：32B头（版本/世界数/
射线数/错误数/输入长度/有效载荷长度），交错工作区和两份查询记录，
末尾16个0x534D494F护栏。输入、源码、产物、参考、全部输出SHA保留。

这一夹具证明查询/生命周期/边界，不能替代完整游戏画质、玩法或FPS。
随后以冻结旧World及其对应玩法片段做同共享库/同核的完整着色像素
对照，再测真实全窗口。负载不同、PIT推进速率不同的轮次不作为软件
收益；预生成画面搬运速度也不当作游戏算法最优上限。
