# SandCore 图形子系统规范 v2.3

> v1 的显存模型、调色板、SCF-8 字体规范继续有效。v2 (M3) 新增：
> **独立绘图模块 gfx（双缓冲）** 与 **SCF-16 中文字体**。
> 对应实现：`kernel/gfx.c`、`kernel/font16.h`。

## 0. 双缓冲架构（v2 新增）

```
绘图 API (gfx_pset/fill/line/circle/text…)
        │  全部画在后台缓冲 (.bss 里的 64000B)
        ▼
gfx_swap()  ──  等垂直回扫 → 整块 u32 拷贝 → 0xA0000 显存
```

- **谁走双缓冲**：整幅画面类的内容（开机画面、dune、about 中文页、
  将来的窗口合成）——画完一帧 swap 一次，永不撕裂。
- **谁走显存直写**：控制台逐字输出（console.c）——终端要的是逐字符
  立即可见，整屏拷贝反而浪费; 代价是 console 自管光标条擦除纪律
  （见 §3.6 的坑录）。
- 后台缓冲本体 = 内核 .bss 的 64000B，`gfx_init()` 清零。

## 0.5 绘图 API（gfx.h）

| 函数 | 说明 |
|---|---|
| `gfx_pset / gfx_get` | 后台缓冲单像素读写（越界裁剪） |
| `gfx_fill` | 实心矩形 |
| `gfx_line` | Bresenham 直线（全整数） |
| `gfx_circle` | 圆，fill 参数选择实心/描边 |
| `gfx_swap` | 垂直回扫同步 + 整块上屏 |
| `gfx_char8 / gfx_text8` | SCF-8 ASCII 渲染（scale 整数放大 + 字距） |
| `gfx_char16 / gfx_text16` | SCF-16 中文渲染，UTF-8 输入，ASCII 自动倍宽混排，缺字画空心框 |

## 1. 显存模型（VGA 模式 13h）

| 属性 | 值 |
|---|---|
| 分辨率 | 320 × 200 |
| 色深 | 256 色（调色板索引色） |
| 帧缓冲物理地址 | **0xA0000**，线性连续 |
| 像素编码 | 1 字节 = 1 像素 = 调色板槽位号（0..255） |
| 寻址公式 | `像素(x,y) = 0xA0000 + y * 320 + x` |

13h 是 VGA 唯一的"链式线性"256 色模式：画点就是一次内存写，不用碰
锻炼端口的位面魔法（mode X 那套），最适合作为自研图形栈的第一块地基。

### 垂直回扫同步（防撕裂）

```
端口 0x3DA (Input Status #1):
  bit3 = 1 表示电子枪正处于垂直回扫期
先等 bit3 变 0 (上一场结束), 再等 bit3 变 1 (新回扫开始) → 安全作画窗口
```

`kmain()` 开头的 `vsync()` 就是这个两段等待。全屏重画前同步一次即可。

## 2. 调色板规范

### 硬件协议

VGA DAC（数模转换器）用两个 IO 端口访问：

```
写 0x3C8 ← 起始槽位号
随后每个槽位连写 3 次 0x3C9 ← 红、绿、蓝
注意: 每个通道是 6 位精度 (0..63), 8 位色值必须 >>2 再写!
```

### SandCore 槽位分配表（自定义，非任何现成方案）

| 槽位 | 数量 | 用途 | 颜色走向 |
|---:|---:|---|---|
| 0 | 1 | 保留黑 | (0,0,0) |
| 1 – 15 | 15 | `PAL_SKY` 天空垂直渐变 | 深靛(28,22,70) → 暖橙(150,90,36) |
| 16 – 23 | 8 | `PAL_SAND_L` 后排沙丘 | 亮沙(125,96,60) → 暗沙(88,68,44) |
| 24 – 31 | 8 | `PAL_SAND_D` 前排沙丘 | 暗沙(100,76,48) → 更暗(70,53,34) |
| 32 | 1 | `PAL_SUN_CORE` 日核 | 金(255,224,130) |
| 33 | 1 | `PAL_SUN_EDGE` 日缘 | 橙(255,166,66) |
| 34 | 1 | `PAL_STAR` 星 | 冷白(170,170,205) |
| 35 | 1 | `PAL_TITLE` 标题/正文 | 米白(235,232,220) |
| 36 | 1 | `PAL_SHADOW` 标题投影/衬底 | 近黑(25,16,20) |
| 37 | 1 | `PAL_CON_BG` 控制台底色 | 深靛灰(16,18,30) |
| 38 | 1 | `PAL_CON_TINT` 控制台强调 | 青(110,200,190) |
| 39 | 1 | `PAL_CON_WARN` 控制台警示 | 琥珀(235,180,80) |
| 40 | 1 | `PAL_PANIC` 异常红屏 | 红(200,45,45) |
| 41 | 1 | `PAL_WIN_TITLE` 窗口标题栏(未聚焦) | 灰(96,100,116) |
| 42 | 1 | `PAL_TASKBAR` 任务栏底色 | 深灰蓝(26,28,40) |
| 43 – 255 | — | 未分配（后续里程碑认领） | |

> 增补槽位的纪律：先在本表认领 → `kernel/palette.h` 加 define → 才能在代码用。
> 渐变段（1-15、16-31）的"第 n 档"语义由绘制代码解释，槽位本身只保证
> "同段内索引越大颜色越深/越暖"。
> 所有槽位的唯一权威定义在 `kernel/palette.h`，本表与它同步修订。

## 3. 自制点阵字体（SCF-8 格式，v1.1）

SandCore 字体**逐位手绘，不抄任何现成字库**（Linux 的 font_8x8、BIOS 字模都不看一眼）。

### 编码格式

```c
static const unsigned char sc_font[95][8];   /* 下标 = 字符码 - 0x20 */
```

- 覆盖完整可打印 ASCII：0x20（空格）到 0x7E（波浪号），共 95 字形
- 每字符 8 字节，1 字节 = 1 行，从上到下排列
- 每字节 **bit7 = 最左像素**，bit0 = 最右
- 渲染时 `(rows[r] >> (7 - c)) & 1` 判断点亮
- 越界字符一律按空格渲染（下标 0 全零行兜底）
- 风格骨架：大写全高、小写 x 字高约 5 像素、主干 2 像素宽 —— 新字形必须延续

### 路线

- M3+：引入 **SCF-16 中文点阵**（16×16，双字节索引，常用字子集按需收录）

## 3.5 中文字体 SCF-16（font16.h，v2 新增）

| 项 | 值 |
|---|---|
| 字形规格 | 16×16 点阵，正楷骨架（横细竖粗），简体简化风 |
| 收字 | M3 历史为 25 字；M6 实际磁盘加载 27 字，本次字库未修改 |
| **字形源文件** | **`kernel/font16.txt`** —— 每字 16 行 `#`/`.`，**归用户 mio 所有，统一凤凰点阵体 CC0** |
| 编译 | make 时 `tools/mkfont.py` 把 txt 编译成 `build/font16_data.h`（改动自动生效） |
| 快速预览 | `python tools/font_preview.py` → `build/font_preview.png`（不用开机） |
| 检索 | 当前字表的 BMP 中文字符按 UTF-8 三字节精确匹配；四字节 Unicode 字符未支持 |
| 缺字策略 | 画空心方框占位——"我不认识这个字"必须看得见 |
| 扩字流程 | **仅通过 `python tools/import_font.py 汉字` 补字** → font_preview.py → make → 截图目检；代理禁止手改 font16.txt |
| 当前默认 | sys/font.scf 来自同一个 font16.txt，12B 头与 276B 字形记录见 FS.md；内置表仅兜底 |
| 字库资源 | 项目根 vonwaon-bitmap.ttf.zip；import_font.py 按脚本位置相对定位，验收包含原资源，解压迁移不读旧绝对路径 |

**新字形的质量门槛**：16px 汉字本质是"有限笔画内的形似"。标准：
远看（缩小 50%）能认出是哪个字；同字重的横竖比例全表一致。

## 3.6 图形控制台（kernel/console.c，M1）

叠在 13h 模式上的自制终端（**不回 BIOS 文本模式**，文字渲染也走自己的图形栈）：

| 项 | 值 |
|---|---|
| 规格 | 40 列 × 23 行，每格 8×8 像素 (自制 SCF-8 字体) |
| 滚动区 | y 0..183（显存整块上移 8 像素行，u32 搬运） |
| 状态栏 | y 184..191，`UPTIME N.NS`，青色，不随滚动 |
| 光标 | 当前格子底部 8×2 横线，**10Hz 心跳驱动闪烁**（0.1s 亮/0.1s 灭） |
| 底色/字色 | PAL_CON_BG / PAL_TITLE（强调用 PAL_CON_TINT） |
| 控制字符 | `\n` 换行+滚动、`\r` 回列首、`\b` 退格跨界、`\t` 对齐到 4 |

### 控制台两条血泪坑（M1 调试实录，改代码前先读）

1. **滚动源偏移**：`fb[i] = fb[i + CELL_H*SCR_W/4]`——写成 `SCR_W/4` 只挪
   1 像素行，滚 26 次才挪 3 行，屏幕全是被"腰斩"的字形残片。
2. **擦除粒度**：擦光标只能擦它自己（格子底部 8×2）或让新字符整格覆盖。
   "整格先擦再画"会在显存留 bg 洞，滚动时洞跟着内容一起滚，留下永久残迹。
   光标条的画/擦只经由 `cursor_sync()` 一个入口（10Hz 驱动），putc 不碰它。

## 4. 绘图 API（M3 将抽成 gfx 模块）

| 函数 | 说明 |
|---|---|
| `pset(x,y,c)` | 画点，带边界裁剪（负数/越界安全） |
| `fill_rect(x,y,w,h,c)` | 实心矩形 |
| `draw_char(x,y,ch,c,scale)` | 画单字符，scale = 整数放大倍数（每像素变 scale×scale 块） |
| `draw_text(x,y,s,c,scale,sp)` | 画字符串，sp = 字符额外间距（像素） |
| `bump(x,cx,half_w,hmax)` | 抛物线"鼓包"地形函数，纯整数运算（256 定点），叠出沙丘轮廓 |
| `vsync()` | 垂直回扫两段等待 |

**整数定点约定**：内核禁用浮点（避免牵扯 libgcc 软浮点），所有曲线用
`256` 定点乘除近似（如 `t*t/256` 即 `(t/16)²` 的抛物线）。这是自研图形
栈的长期约定，写新特效时遵守。
